## What was done

* `fxd::container` — the append-only log. Header magic `FOTOXFXD`, version 1,
  writer string, reserved zero. Chunk header `kind u8, flags u8, reserved u16,
  payload_len u64, crc32 u32`. Footer magic `FXDEND01`, manifest offset/length,
  end offset, live bytes, CRC over bytes 0..60.
* All I/O is **positional**: `read_exact_at` loops over short `seek_read`s
  (SNIPPETS §12), `write_all_at` does the same for writes. Because every
  access carries its own offset, the cursor `seek_read`/`seek_write` move on
  Windows is irrelevant, so the reader and writer can share one handle.
* `FxdWriter::{create, append_to, tile, preview_tile, manifest, commit}`.
  `commit` is `sync_data → footer → sync_data`, so the previous footer stays
  valid until the new one is durable.
* `FxdFile::open` validates magic/version, finds the newest valid footer,
  returns `Arc<FxdFile>` + `Footer`; `read_chunk` verifies the payload CRC
  before returning anything.
* `find_footer` scans backwards in 1 MiB blocks overlapping by 63 bytes and
  accepts a footer only when its CRC is valid **and** `end_offset == position + 64`
  (SNIPPETS §13) — the magic alone can occur inside compressed tile data.
* `parse_tile_payload` parses/validates a tile payload header (format, codec,
  `uncompressed_len == format.tile_bytes()`).
* `sniff` recognises `FOTOXFXD`; `import_file` refuses `.fxd` with a message
  pointing at the lazy opener (M3-T05).

Tests: round trip of every chunk kind (TILE / PREVIEW_TILE / MANIFEST); a
flipped payload byte → `Decode("corrupt chunk at …")` (tile and manifest); the
file truncated at **every** byte offset of the last save opens the previous

`Unsupported("fxd version 2")`; tile payload header validation.

## Deviations from the task card

* `fx-io/Cargo.toml` beyond "the checksum crate and zstd": the JSON manifest
  (M3-T02) needs `serde` and `serde_json`, both already approved workspace
  dependencies (no new crate, no DECISIONS entry needed).
* Added `FxdWriter::preview_tile` and `FxdFile::{footer,id,path,position}` plus
  `parse_tile_payload`; `commit`'s public API is unchanged. The card's `tile()`
  only writes TILE, but PREVIEW_TILE chunks must be writable (M3-T04).
* `import_file` needed an arm for the new `Sniffed::Fxd` variant (exhaustive
  match); it returns a clear error instead of guessing.
* `FxdFile` is `Clone` (shares one `Arc<File>` + its id); `append_to` takes
  `FxdFile` by value as the card specifies, so callers pass a clone of the
  opened file.

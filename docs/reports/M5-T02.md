# M5-T02 — Viewport overlays

Agent: Buffy (Codebuff)  ·  Branch: `m5`  ·  Status: ready for review

## Plan (written before coding)

- `fx-render/src/overlay.rs`: the `Overlay` model in document coordinates and
  a pure `tessellate` to screen-space triangles, unit-tested.
- `gpu/overlay.wgsl` + a second pipeline in `gpu/viewport.rs`, drawn in the
  viewport pass after the tiles, one draw call; the arc-length dash and a time
  uniform animate the ants in the fragment shader.
- `Frame::overlay`; the render thread tessellates each frame and redraws at
  8 Hz while an `Ants` overlay is visible (otherwise only on change).

## What was done

- **Model** (`overlay.rs`): `Overlay { items }` with `Polyline { points,
  closed, style }`, `Circle { centre, radius, style }`, `Handle { at, size_px }`
  and `Crosshair { at }`; styles `Ants`, `Solid(colour)`, `Xor` (a black 3 px
  halo under a white 1 px core). `has_ants()` tells the render thread to
  animate.
- **Tessellation** (pure, tested): one quad per segment carrying the arc length
  so the ants dash continuously across joins; screen-space line width, so the
  line stays 1 px at any zoom; a `Handle` is a screen-sized square, a
  `Crosshair` two short `Xor` arms.
- **GPU** (`overlay.wgsl`, `gpu/viewport.rs`): a second pipeline (screen-space
  vertices from a storage buffer, premultiplied blending) drawn in the same
  render pass after the tile quads. The fragment shader picks black/white from
  `fract((arc − time·30 px/s) / 8 px)`.
- **Render thread** (`render.rs`): `Frame` carries `overlay: Option<Arc<Overlay>>`;
  the render thread tessellates with the current view (a hover never touches
  the compositor) and, while the overlay has ants, switches from a blocking
  `recv()` to `recv_timeout(125 ms)` so it redraws at 8 Hz; a timeout redraws
  the same frame with a newer time.
- **Tools** (`tools/mod.rs`): the `Tool` trait gained `overlay()` (default
  `None`), and `request_frame` asks the active tool for it (M5-T03 supplies the
  selection contour).

## Deviations from the task card

- The overlay is drawn in the **same** render pass as the tiles (the card says
  "in the viewport pass, after the tiles"), rather than a separate pass; the
  call simply gained `overlay` and `time` arguments.
- The card's `Handle { at, size_px }` is implemented as a screen-sized square,
  as described. No caller uses it yet (transform handles are M6).
- Nothing produces an overlay in this slice, so the 8 Hz timer never runs in
  the app until M5-T03 wires the selection contour; the animation decision is
  unit-tested (`has_ants`) and the shader path is covered by the GPU test.

### B-01  A drop-down on the option bar never reaches the engine   severity: ux
- Where: `ui/js/optionsbar.js:234-249` (`select().onPick`), with `ui/js/popup.js:133-160`
  (the rows live in `#popuplayer`, outside the bar) and `ui/js/optionsbar.js:135-146`
  (`onOptionsChange` listens on the *container*).
- Proof (exact steps): open the app. `B` (Brush). Open the **Mode** drop-down and pick
  `Multiply`; the bar shows `Multiply`. Paint: the stroke is **Normal**. The engine only
  receives `ToolOptions` when the container sees an `input`/`change`/`click` (`main.js:233`
  → `sendToolOptions`), and a pick is a click on a row of `#popuplayer` with
  `e.stopPropagation()`; `onPick` (line 244-247) sets the label and calls `changed()`, which is
  `sync` — it re-runs the `enables` greying and **never notifies**. `emit("mock", …)` is only a
  toast (`main.js:278`). Any later change of another control re-sends the whole set, so the value
  finally lands then — which is exactly why this went unnoticed.
- Cause: the toggle bug fixed in `e91f290` (a click that stops propagation must tell the bar) was
  never applied to `select`: the dropdown's `onPick` is the only place the value changes and it
  does not call `changeHandler`/dispatch a `change`.
- Class: 3 (UI → engine plumbing that silently does nothing).
- Fix idea: in `onPick`, dispatch a bubbling `change` on the control (or call the bar's
  `notify`) after setting the value, exactly as `toggle` now does.
- Blast radius: every `select` in `ui/js/data/options.js` — Brush/Pencil/Clone/… `Mode`,
  `marquee` `Style`, `crop` `Ratio`/`Fill`, `eyedropper` `Sample Size`/`Sample`, `gradient`
  `Type`/`Method`, `type` `Font`/`Style`/`Anti-alias`, `dodge`/`burn` `Range`, `sponge` `Mode`,
  `paint-bucket` `Fill`, `color-replace`/`eraser-bg` `Sampling`, `pen` `Mode`, …

### B-02  Eyedropper ▸ Show Sampling Ring is sent and read by nobody   severity: ux
- Where: `ui/js/data/options.js:110` (the toggle) vs `crates/fx-engine/src/tools/eyedropper.rs`
  (`Options` has only `area` and `current_layer`; nothing draws a ring).
- Proof: the only occurrence of the string in the tree is the settings unit test
  `crates/fx-engine/src/tools/mod.rs:795,799`; the tool's overlay (`overlay()`) returns nothing,
  so toggling it in the app changes nothing. (Show Mesh / Contrast *are* read —
  `tools/puppet.rs:132`, `tools/magnetic.rs:50` — this one is not.)
- Cause: the option was added to the bar with the rest of the M5-T01 eyedropper bar but the
  sampling ring itself was never drawn, and the only "read" is in a test, which makes a naive
  string grep look like a live read.
- Class: 3 (an id that is only *mentioned* is not necessarily handled — the same trap the
  `implemented.js` generator notes).
- Fix idea: drop the toggle from the bar, or read it in `Options::from` and emit a ring overlay.

### B-03  Eyedropper ▸ Sample Size "11 by 11" / "51 by 51" silently point-sample   severity: wrong-result
- Where: `crates/fx-engine/src/tools/eyedropper.rs:32-36` (`Options::from`: only `"3 by 3
  Average"` and `"5 by 5 Average"`, everything else `_ => 1`), against the bar's five choices at
  `ui/js/data/options.js:110`.
- Proof: `#[ignore = "bughunt: B-03"]`
  `tools::eyedropper::tests::the_samples_sizes_the_option_bar_offers_are_the_ones_the_reader_knows`
  — `cargo test -p fx-engine --lib eyedropper -- --ignored` fails with
  `left: 1, right: 11` at `Sample Size "11 by 11 Average"`.
- Cause: the sibling tester's reader (`crates/fx-engine/src/engine/m9.rs:82-89`, the Color
  Sampler) was widened to 11/31/51/101; the eyedropper's was left at the 1/3/5 it started with —
  and `sample_pixel`'s doc comment ("`area` — 1, 3 or 5") confirms the wider sizes were never

- Class: 3 (a value the UI offers that the reader does not know → a silent wrong result, not an
  error).
- Fix idea: handle 11 and 51 in `Options::from` (the sampler's match is the template) and update

## Checked and clean (do not re-check)

- **Tile/level spaces.** `render-shaped`/`render_text_tile`/`render_fill_tile`/
  `render_vector_mask_tile` all map `level pixel → document = (i + 0.5)·2^L` and subtract the tile
  origin once; verified by hand at level 1/2, tile (0,0)/(1,0)/(1,1), with a layer offset. The
  compositor's pixel-layer offset rounding and the effects' `read_alpha` offset use the *same*
  formula (`program.rs:736`, `effects.rs:239`), so the two agree by construction.
- **`Permutation`.** `mapping` (continuous, `h − y`), `source_pixel` (index, `h − 1 − y`), `size`
  and `offset` are mutually consistent; `fx-ops::permute` round-trips pixel-exactly for all five
  ops on non-tile-aligned sizes (existing tests).
- **Mip cache.** `needs_compute`/`collect_needed`/`compute_tile` recompute exactly the dirty or
  evicted ancestors, and level-0 is never recomputed.
- **Render-thread caches.** `ready` is kept across generations (deliberate, the flicker fix),
  `programs` is keyed by generation, `mips_sent` by snapshot identity, and `keep_or_forget`
  protects a stale slot for the frame it is shown in. `frame` returns "draw again" only while
  progress or upload budget was spent.
- **Serialization.** `LayerKindEntry`'s only `flatten` collision (`fill` vs `shape_fill`) is fixed
  and has a file round-trip test; `LayerEntry`'s other fields do not collide with any variant's
  fields (`id, name, visible, opacity, fill, blend, clipped, locked_*, mask, styles, vector_mask,
  artboard`); `FillLayer`'s tag is nested under `content`; unknown manifest fields survive.
- **Commands.** `History::execute` clones, restores on error and only then records; the two
  `apply` calls outside it (`tools/move_tool.rs:47` preview, `tools/type_tool.rs:98/177` live text)
  operate on a document clone or an over-writable field, and the type tool restores the whole
  snapshot on cancel.
- **Blend modes.** All 27 checked against the W3C formulas (`blend_channel`, `set_lum`,
  `set_sat`, `clip_color`, `composite`); Overlay is HardLight with swapped args, SoftLight matches
  the piecewise form, ColorBurn/ColorDodge have the right edge cases (existing tests).
- **Gradients.** `t_at` (five geometries, reverse, clamp), `midpoint`, Oklab/Linear/Classic mix and
  the Bayer dither are consistent; a fill layer's `placed()` folds Angle/Scale/Offset correctly.
- **Align/Distribute.** `align:*` signs are right for all six anchors and `dist:*` keeps the first
  and last and spaces the rest on the right axis.
- **Selection algorithms.** `flood`/`magic_wand`, `morph::modify` (feather/expand/contract/border/
  smooth) and `select::grow` (`colour_table` dilation, boundary seeding, cross-tile flood, and the
  `edt_2d`/`edt_1d` transform) are correct at tile boundaries; `block_coverage` reads up to four
  canvas tiles and zeroes outside the canvas without underflow.

## What was done

This is an environment/bring-up task: no code was written. The vendored shell
and the engine crates build on the reference machine.

**Prerequisite audit.** Five of the six prerequisites were already present.
CMake was missing, and it is a hard blocker: `cef-dll-sys` builds
`libcef_dll_wrapper` with `cmake -G Ninja`, so both `cargo build -p fx-app` and
`cargo clippy --workspace` fail without it. Rob approved installing it;
installed **CMake 4.4.3** with
`winget install --id Kitware.CMake -e` (machine-wide, `C:\Program Files\CMake\bin`,
already in the machine `PATH`). Nothing was installed globally beyond that, and
no tool versions were changed.

**Checks run, in the order of the card.** `cargo fmt --check` was already clean.
`cargo test` at the root never touches CEF, as designed by `default-members`:
64 tests green. `cargo clippy --workspace --all-targets -- -D warnings` was the
check that exposed the missing CMake; after the install it is clean
workspace-wide, which is the strongest available proof of the "no warnings in
our crates" acceptance. `cargo build -p fx-app` then succeeded, downloading CEF
once into `third_party/cef/151.3.24/cef_windows_x86_64` (592 MB on disk).

## Open problems / suggestions

1. **`cargo clippy --workspace` is not the check the card intends.** It pulls in
   `vendor/graphite` and CEF, so an environment problem (a missing CMake) fails
   a *code quality* gate with an error from someone else's build script. The
   AGENTS.md §4 clippy line is fine, but it now implies CMake is needed for
   every code edit on this machine. Consider splitting it: clippy for the ten
   `fx-*` crates as the per-commit gate, and clippy for `--workspace` only in
   the pre-push/release check.
2. **`ninja` on PATH is the pip-installed one** in
   `AppData/Local/Programs/Python/Python310/Scripts`. It works, but it is not
   the Kitware build the card implies, and it will vanish if that Python
   environment is ever recreated. Worth pinning down before M0-T02, which
   automates bundling.
3. Everything in this task is manual and undocumented for a clean machine. The
   M0-T07 checklist wants the `README.md` "Run" section verified on a clean
   clone — a `docs/SETUP.md` with the exact versions above (and the winget
   command) would make that repeatable.
4. The report template has no slot for tool versions, which this card asks for
   explicitly. A "Toolchain" section would fit M0-T01 and any later task that
   depends on the environment.

# M5-T04 — Selection tools (marquee, lasso, polygonal lasso)

Agent: Buffy (Codebuff)  ·  Branch: `m5`  ·  Status: ready for review (slice; the
magic wand and moving the outline follow)

## Plan (written before coding)

- `fx-engine/src/tools/marquee.rs` and `lasso.rs`: the six tool ids the tool
  data already has (`marquee`, `marquee-ellipse`, `marquee-row`, `marquee-col`,
  `lasso`, `lasso-poly`), driven entirely by pointer events and the option bar.
- The drag is *previewed*, not applied: the tool keeps the shape in progress
  and returns it as an `Ants` overlay (M5-T02), and the release sends one
  `Command::Select` (R1) — so a drag is one History step and the selection
  rasteriser is never run per mouse move.
- `ToolResult.redraw` for that preview: an overlay-only redraw. The engine
  re-plans the frame but every tile is a cache hit, so nothing is recomposited
  (the same path the 8 Hz ants animation uses).
- A `UiToEngine::Key` message for the keys the tools need (Escape, Enter,
  Backspace): the UI's shortcut map owns the keyboard, so the polygon cannot be
  closed any other way.
- Tests drive each tool with synthetic pointer/key sequences and check the
  command, the overlay and the modifier rules.

## What was done

- **Marquee** (`tools/marquee.rs`): drag to a rectangle/ellipse, one command on
  release. Shift at press = Add, Alt = Subtract, Shift+Alt = Intersect, Else
  the option bar's Mode button group (the bar sends the index; a wording works
  too). While dragging Shift constrains to a square/circle, Alt draws from the
  press point as the centre, and Space grabs the marquee and moves it. Style:
  Normal, Fixed Ratio (w : h from Width/Height) and Fixed Size (a click makes
  the selection; a drag repositions it). A release under 3 *screen* pixels is a
  click: with Replace it sends `Deselect` (Photoshop), with Add/Subtract/
  Intersect it does nothing. Single Row/Column select on the press, no drag.
  Escape drops a marquee being drawn. Feather and Anti-alias come from the bar.
- **Lasso** (`tools/lasso.rs`): freehand samples the pointer every 0.5 *screen*
  pixels (so a slow drag at fit does not store thousands of points) and closes
  on release; a click (fewer than three points) clears the selection. Polygonal:
  a click adds a point, the rubber band runs to the pointer, and the path closes
  on Enter, a double-click (two presses within 400 ms and 5 screen pixels) or a
  click on the first point; Backspace/Delete drops the last point; Escape
  cancels. Both draw the path as an `Ants` polyline while it is open.
- **Protocol**: `UiToEngine::Key { key }`, named like the DOM's
  `KeyboardEvent.key`, plus a round-trip test and a `docs/PROTOCOL.md` §4 row.
- **UI**: `shortcuts.js` forwards Escape/Enter/Backspace/Delete to the engine
  when no dialog is open and no field has focus; the option bar's Mode button
  group now reports under the key `Mode` (schema `key`, `optionsbar.js`
  `keyOf`), Style ▸ Width/Height are greyed out unless the Style asks for them
  (`enables` in the option data), and the Select menu's Deselect/Reselect/
  Inverse items are live.
- **Engine**: `tool_key` routes a key to the active tool; `apply_tool_result`
  requests a frame for `redraw` *before* running a command (so the overlay
  reflects the state the tool just left); `Select ▸ All/Deselect/Reselect/
  Inverse` (`sel:*`) now run the M5-T03 commands, and Deselect/Reselect stay
  quiet when there is nothing to do instead of toasting an error; the tools'
  idle cursor takes over the view's plain-hover `Default` (the marquee's
  crosshair, the same fix the eyedropper needed); `Documents::get` and
  `ToolContext.view` (the zoom the screen-space thresholds need); the tool ids
  Fotox has not reached (magic wand, quick/object selection, magnetic lasso)
  are a `NotYet` placeholder that says so in a toast on a click.

The tool tests pin: the rubber band's four corners and its `Ants` style; the
release command's shape/mode/feather/anti-alias for every modifier combination;
Shift keeping the marquee square and Alt centring it; Space moving it by the
pointer's travel; a click deselecting in Replace and doing nothing in Add; the
click slop being a *screen* distance (the same 2 px drag is a click at 25 % and
a marquee at 400 %); the ellipse preview's 64 points on the ellipse; Fixed Size
and Fixed Ratio; row/column selecting on the press; the freehand sample step at
two zooms; the polygon closing three ways plus Enter/Backspace/Escape. Through
the engine: a marquee drag from viewport (100, 100) to (300, 250) on a 700 × 400
document records one "Rectangular Marquee" step and no `document_changed`; a
cancelled drag records nothing; three clicks and Enter record one "Lasso" step.

## Deviations from the task card

- **Not implemented in this slice** (the card's own later half):
  - **Magic Wand** and `fx-ops/src/flood.rs` (tolerance, contiguous scanline
    fill across tiles, Sample All Layers).
  - **Moving the outline**: dragging inside the selection to `OffsetSelection`,
    and the arrow keys (1 px / Shift+arrow 10 px).
  - **Alt in the freehand lasso** switching to polygon segments.
  - Quick Selection / Object Selection / Magnetic Lasso *implementations*: the
    card puts them out of scope; they now answer with a toast instead of
    silence.
- The option bar's Mode control is a button group, so the engine reads its
  index (0 New … 3 Intersect); a wording is accepted as well.
- Fixed Size anchors the press point as the marquee's **corner** and a drag
  repositions it, rather than centring it. VERIFY against Photoshop.
- The four `sel:*` menu items are always enabled: the UI does not know the
  selection state yet (T05/T10 will drive it from `document_changed`). The
  engine ignores a Deselect/Reselect that has nothing to do.
- `UiToEngine::Key` is new: the card assumes the tools can see Escape/Enter/
  Backspace, and keyboard input reaches the UI (CEF), not the engine
  (`docs/ARCHITECTURE.md` §2.2).

  check the rubber band, Shift/Alt/Space during the drag, and that Escape
  cancels. Then the polygonal lasso with Enter/Backspace/double-click.
- The rubber band redraws once per pointer event, and each redraw re-plans the
  frame (tiles are cache hits, so no recomposite). On a 30 000² document at fit
  that is the interesting number for S14; if it shows, the plan itself should be
  cached per view.
- The `Ants` animation timer (8 Hz) also fires while a rubber band is up, so
  the preview crawls; the geometry is only as fresh as the last pointer event,
  which is what Photoshop does.
- `NotYet` is a placeholder, not a design: when the wand lands it should replace
  `magic-wand` in the registry rather than sit next to it.

## What was done

`crates/fx-engine/src/layers.rs` (new) — `pub fn layer_infos(doc: &Document)
-> Vec<LayerInfo>` flattens the layer tree into the list the `layers` message
carries (`docs/PROTOCOL.md` §5):

* **Order** is Layers-panel order, top → bottom: every sibling list
  (`Document::layers`, a group's `children`) is walked back to front, and a
  group is emitted *before* its children, so a group row sits above the rows
  it contains. `depth` counts group nesting (0 for root layers); the flat list
  plus `depth` is the whole tree, exactly as `LayerInfo` documents.
* **Field mapping**: `id`, `name` (cloned), `visible`, `opacity`, `fill`,
  `blend`, `clipped` and `selected` (`Document::selected`) pass through
  unchanged; `kind` maps 1:1 (`Pixel`/`Group`/`Adjustment`/`SolidFill`);
  `depth` as above; `expanded` is `true` only for a group with
  `expanded: true`; `has_mask` is "a mask exists" (a *disabled* mask still
  gets its row indicator, like Photoshop's red X); `locked` is
  `locked_pixels || locked_position`.
* No tile is read, no `TileStore` is involved and no allocation is
  proportional to the document's pixel size — the function is `O(layers)` and
  can be called for every `layers` message on a 30 000² document.

Tests (all in the new file, 9 of them): panel order + depths for a document
with a nested group; every `LayerKind` → `LayerInfoKind`; every flag and
property (`visible`, `opacity`, `fill`, `blend`, `clipped`, mask, both locks);
`expanded` from groups only; multi-selection mirrors `Document::selected`;
selection of a deleted id is ignored; empty document → empty list; a group
without children is a single row.

`crates/fx-engine/src/lib.rs` — one added line, `pub mod layers;`. The module
is `pub` rather than re-exported so the public path is
`fx_engine::layers::layer_infos`; nothing else in the file changed.

## Deviations from the task card

1. **Scope.** Only the `fx-engine` conversion from M2-T01 is on this branch.
   The card's main body — every `M2` command in `fx-core::command`
   (`AddLayer`, `DeleteLayers`, `DuplicateLayers`, `MoveLayer`, `OffsetLayer`,
   `AddMask`, `DeleteMask`, …) with validation-first semantics, effects and
   undo/redo tests — is not implemented here. That is the other lane; the
   report will be split or superseded when it lands.
2. **`locked` is the OR of `fx-core`'s two locks.** `LayerInfo` carries a
   single `locked` bool for `locked_pixels` *and* `locked_position`
   (`fx-protocol`, which this lane must not change). I map it to "locked in
   some way", matching the single lock icon Photoshop draws per row, rather
   than only pixel locks. M2-T06's "lock toggles" (plural) need either the UI
   to drive both flags together or a second protocol field — see Suggestions.
3. **`expanded` is `false` for non-groups** (the flag only exists inside
   `LayerKind::Group`) and **`has_mask` is `mask.is_some()`**, i.e. it ignores
   `Mask::enabled`; a disabled mask is still shown in the row.
4. **`cargo clippy --workspace` cannot run in this checkout.** `--workspace`
   includes `vendor/graphite/desktop-ui`, whose `cef-dll-sys` build script
   needs `cmake`; `cmake` is not installed on this machine
   (`failed to execute command: program not found / is cmake not installed?`).
   This is pre-existing and unrelated to the task. I ran
   `cargo clippy --all-targets -- -D warnings` instead, which lints every
   default member — i.e. `AGENTS.md` §4's list minus `fx-app` — and it is
   clean. `cargo build -p fx-app` was not run either: this task touches none
   of `fx-app`, `vendor/` or `ui/`, and `CEF_PATH` was set to the shared
   `fotox/third_party/cef` as instructed.
5. **`pub mod layers;` instead of a re-export.** My lane allows one `mod`
   line in `lib.rs`; making the module `pub` keeps the public item reachable
   (`fx_engine::layers::layer_infos`) within that budget. Say the word if you
   prefer a flat `fx_engine::layer_infos` re-export.

## Open problems / suggestions

- **Protocol gap for locks.** One bool cannot represent two independent locks.
  If M2-T06 wants Photoshop's separate lock toggles, `LayerInfo` needs a
  second field (`locked_position`/`locked_pixels`) — an `fx-protocol` change
  plus `PROTOCOL.md` and `ui/js/native/protocol.js`, outside this lane.
- **The message builder.** Building the actual `EngineToUi::Layers { doc,
  revision, layers }` (and sending it when `CommandEffect::structure_changed`
  or `props_changed` is set) belongs to the engine thread (M0-T04, M1-T08);
  only the conversion is here.
- **Dead-layer guard.** `layer_infos` is a pure function of the document, so a
  `layers` message is only sent when the engine decides something changed.
  Nothing enforces that invariant yet; the engine thread should key on
  `Document::revision` + selection to avoid resending with 1 000 layers.
- **Cost test** (optional): a `#[test]` that flattens 1 000 nested layers and
  asserts it finishes without touching the `TileStore` would pin the
  `O(layers)` claim down; not written because there is no store to assert
  against yet.

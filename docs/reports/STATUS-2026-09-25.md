## What to test (in this order)

Before anything: CMake must be on `PATH` in the shell that runs cargo (`C:\Program Files\CMake\bin`).

1. **Start the app** — `cargo xtask run`. Window opens with the Fotox UI and the test pattern (no document open). Check: menus, a dialog, typing, Escape, resize, the window buttons; **125 % / 150 % Windows scaling** (not tested yet); closing leaves no `fotox.exe`.
2. **Pan / zoom on the test pattern** — wheel, Shift+wheel, Ctrl+wheel (point under the cursor stays put), middle-drag, Space+drag, `Ctrl+Alt+F` for the overlay. A menu open over the canvas must take the clicks.
3. **Make the benchmark files** (release, in `bench/data/`):
   ```bash
   cargo run -p fx-cli --release -- gen bench/data/B1.tif --width 30000 --height 30000 --bits 16
   ```
   ```bash
   cargo run -p fx-cli --release -- gen bench/data/B2.tif --width 30000 --height 30000 --bits 8
   ```
   Target: B1 < 2 min, peak RAM < 500 MB; generate B1 twice and compare SHA-256 (same seed → same file).
4. **Engine benchmarks** → rows in `bench/results.csv`:
   ```bash
   cargo run -p fx-cli --release -- bench import --file bench/data/B1.tif
   ```
   ```bash
   cargo run -p fx-cli --release -- bench mips --file bench/data/B1.tif
   ```
   ```bash
   cargo run -p fx-cli --release -- bench trim
   ```
   Targets: import ≥ 80 % of raw read (`import_vs_raw`), full pyramid ≤ 10 s.
5. **Open B1 in the app** (Ctrl+O, drag & drop, or `cargo xtask run --release -- bench/data/B1.tif`): progress in the status bar, then the document. **S2**: fit ↔ 3200 %, ≥ 60 fps, never a black tile, full detail < 250 ms after stopping (overlay + PresentMon). Open B2 and a PNG in more tabs, switch, close them all → RAM back near the start value.
6. **Layers / History** on any document: new layer, rename (double-click), eye, opacity (type, or drag the "Opacity:" label), blend mode, locks, drag rows (above/below/into a group), Ctrl+G, Ctrl+J, Alt+Ctrl+G, delete; Ctrl+Z / Ctrl+Shift+Z / Ctrl+Alt+Z and clicking History rows. Add a Hue/Saturation or Brightness/Contrast layer from the panel's adjustment button, then double-click its icon: the dialog edits it live.
7. **Export** — *File ▸ Export ▸ PNG* (and *TIFF*) on an open document: save dialog, progress in the status bar, toast "Exported …"; open the file in Photoshop.
8. **B3** — with B1 open: `Other ▸ Benchmarks ▸ Load B3 onto This Document` → S4 (toggle visibility / blend of a mid-stack layer), S5 (drag its opacity: ≥ 30 fps; the hot-layer cache engages after 2 edits within 1 s), S6 (a Curves layer on top), S8 (RAM ≤ 10 GB).

## Open points / decisions for you

* **JPEG import is not streamed** (decoded whole: `width × height × 4` bytes). Fine for normal photos; a decision if 30 000² JPEGs matter (M1-T09 report).
* **Formulas to verify against Photoshop (M7)**: Brightness/Contrast curves, Hue/Saturation (M2-T04 report).
* ~~Levels / Curves dialogs cannot edit adjustment layers live~~ — done later the same morning (`M2-levels-curves.md`): real curve editor, per-channel settings, a new adjustment layer opens its dialog.
* **B3 layers** are single-colour rectangles with feathered edges, not photographic content (M2-T08 report explains why; easy to change).
* **One black UI frame** was seen once right after loading B3 (M2-T08 report) — watch for it.
* Protocol additions (all backwards compatible, documented in `PROTOCOL.md`): `status` frame statistics; `LayerInfo.locked_pixels / locked_position / adjustment / fill_color`.
* **M3 cards drafted** (`docs/tasks/M3.md`, not approved): card M3-T00 lists six decisions for you (checksum crate, zstd vs LZ4 for tiles, JSON manifest, preview chunks, keeping the file open, JPEG encoder crate). Nothing of `.fxd` is coded until you decide.
* **Flat export works** (`M3-export.md`): *File ▸ Export ▸ PNG / TIFF* in the app → save dialog → streaming export with progress. Alpha only when the document is not opaque, the document's bit depth and ppi, CPU compositor (slow on B1). Not tried in the app yet.

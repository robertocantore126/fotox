# M3-T03 — Backed tiles (`fx-tiles`)

Agent: Buffy (Codebuff)  ·  Branch: `task/M3-T03-backed-tiles`  ·  Status: ready for review

## Plan (written before coding)

1. Add a fourth copy `backed: Option<Backed>` to `Copies`, with the `TileSource`
   trait and `Backed` struct as specified.
2. `TileStore::insert_backed` (no copy, nothing read),
   `attach_backing`, `TileHandle::backing`.
3. `get`: hot → warm → cold → **backed** (read + decompress, verified format),
   counted in a new `TileStoreStats::backed_reads`.
4. Trim: a backed tile frees all RAM and its scratch extent.
5. Tests for each behaviour, then the M3-T02 `from_manifest` + `impl TileSource
   for FxdFile` and the Document round-trip (this branch carries both, since
   M3 is built by one agent).

## What was done

* `fx_tiles::TileSource` (`read(offset, len, format)`, `id()`) and
  `fx_tiles::Backed { source: Arc<dyn TileSource>, offset, len }`.
* `Copies` gained `backed`; `is_empty` accounts for it (an authoritative tile
  always has ≥ 1 copy).
* `TileStore::insert_backed(format, class, backed)` — creates the entry with
  only the backed copy, reads nothing.
* `TileStore::get` reads the source when no copy is in RAM (or scratch),
  checks the returned format, and installs the result as the hot copy. The
  tile's lock is held across the read, so concurrent waiters share one read.
* `TileStore::attach_backing(handle, backed)` and the `release_backed_copies`
  pass at the start of `trim`: a backed tile gives up its hot/warm copies and
  frees its cold extent (it can always be read again).
* `TileHandle::backing() -> Option<(u64, u64, u64)>`.
* `fx_io::fxd::manifest::from_manifest` — builds a `Document` whose tiles are
  backed by the opened file, nothing is read; levels 1–2 are left dirty so the
  renderer rebuilds them.
* `impl TileSource for FxdFile` — verifies the chunk checksum, parses the tile
  header, decompresses (raw / zstd / lz4) and returns the pixels.

## Verification

```text
$ cargo fmt -p fx-tiles -p fx-io -p fx-core -- --check     (clean)
$ cargo clippy -p fx-tiles -p fx-io -p fx-core --all-targets -- -D warnings
Finished `dev` profile [optimized + debuginfo] target(s)
$ cargo test -p fx-tiles       32 passed; 0 failed
$ cargo test -p fx-io          38 passed; 0 failed (incl. the file round trip)
```

`fx-tiles` tests: get of a backed tile = the right pixels (read on demand);
dropping the last handle reads nothing; trim leaves a backed tile with no RAM
and no scratch; `attach_backing` then trim frees the scratch extent; 8
concurrent gets read the source exactly once.
`fx-io` test `the_sample_document_round_trips_through_a_file` writes the
sample document to a real `.fxd`, reopens it, rebuilds it with `from_manifest`
(all tiles backed) and compares both documents layer by layer and pixel by
pixel through `store.get`.

## Deviations from the task card

* The card assigns `fx-tiles` changes to M3-T03 and `from_manifest` to
  M3-T02. With one agent building M3, both live here: `from_manifest` needs
  `insert_backed`, which did not exist when T02 was committed. See the updated
  M3-T02 report.
* `fx-io` gained `lz4_flex` so the reader honours the lz4 codec byte (no writer
  produces it yet).

## Open problems / suggestions

* `trim()` now scans all live entries on every call to free backed RAM even
  when under budget. The background thread only calls it when over budget, so
  the cost is bounded; a dedicated "backed dirty list" could remove the scan
  if profiling asks for it.

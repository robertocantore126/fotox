# M5-T01 — Tools reach the engine

Agent: Buffy (Codebuff)  ·  Branch: `m5`  ·  Status: ready for review

## Plan (written before coding)

- Protocol: `ToolOptions`, `SetColors` (UI → engine) and `ColorPicked`
  (engine → UI), serde round trips; mirror the names in `protocol.js`; answer
  in `mock-engine.js`; document in `PROTOCOL.md`.
- Engine: `DocPointer` in document coordinates; `ViewState::pointer` reports
  whether the view consumed the event (pan/zoom keeps priority); a `Tool`
  trait + registry in `tools/`; unconsumed events go to the active tool.
- First tool: the Eyedropper, sampling one tile with the CPU reference
  compositor; answers `ColorPicked`.
- UI: `readOptions()` / `onOptionsChange` on the option bar; `main.js` sends
  `ToolOptions` on tool change and every option change, and `SetColors` on
  every colour change; `ColorPicked` updates the swatch.

## What was done

- **Protocol** (`fx-protocol`): `UiToEngine::ToolOptions { tool, options }`,
  `UiToEngine::SetColors { fg, bg }`, `EngineToUi::ColorPicked { rgba, target }`
  with a serde round-trip test each.
- **View routing** (`view.rs`): `pointer` now returns a `PointerOutcome`
  (`changed` + `consumed`). Pan gestures — middle button, Space + left, the
  Hand tool — stay consumed; everything else (`consumed == false`) goes on to
  the active tool. A new view test asserts a plain left click is not consumed.
- **Tools** (`fx-engine/src/tools/`): `DocPointer`, `ToolResult` (command /
  picked colour / cursor / status line), `ToolSettings` (fg, bg, per-tool
  option JSON with typed getters), the `Tool` trait and a registry that
  creates a tool on first use. `engine.rs` maps the pointer through the inverse
  view transform, calls the active tool and applies its answer: a command
  through `History`, `ColorPicked` to the UI, the cursor, a toast.
- **Eyedropper**: Point Sample / 3 by 3 / 5 by 5 and All Layers / Current
  Layer. `sample_pixel` composites **one tile** with `build_program` +
  `render_tile` (the CPU reference compositor), averages the square and
  un-premultiplies; the cost does not depend on the document size. Alt picks
  into the background swatch.
- **UI**: `optionsbar.js` gained `readOptions()` and `onOptionsChange`
  (listeners wired once); `main.js` sends `ToolOptions` when a tool becomes
  active and on every change, and `SetColors` from the `colors` event (toolbar
  swatch, X, D, eyedropper answer); `native/tools.js` is the new colour
  transport and `ColorPicked` handler; the mock engine accepts the two new UI
  messages and answers `ColorPicked` for a `debug:pick-color` action (browser
  mode has no pointer routing).

## Deviations from the task card

- The card puts sampling on `PixelOps`; it is a free function
  (`tools::sample_pixel`) instead. `PixelOps` exists for algorithms a
  *command* needs (R1a) — the eyedropper is a view-time query, so adding a
  method to the public trait would widen it for no gain.
- The `Tool` trait has no `overlay()` yet; the `Overlay` type arrives with
  T02, which adds the method (noted in the module docs).
- `ui/js/state.js` and `ui/js/shortcuts.js` needed no change: shortcuts already
  go through `setTool` → the `tool` event, and colours through
  `state.setColors` → the `colors` event, which `main.js` now forwards.
- `serde_json` moved from `[dev-dependencies]` to `[dependencies]` in
  `fx-engine` (it is already a workspace dependency, used by `fx-protocol`);
  no new crate, so no `DECISIONS.md` line.

## M1-T07 — render loop (`fx-engine/src/render.rs`)

Per frame, when a document is active (card steps 1–6):
1. `compositor.begin_frame()`.
2. `plan_frame` with a `ready` map for the current (document, revision); cleared when either changes.
3. Programs for `plan.requests` (≤ 256 per frame) **plus every ready tile the plan looked at** — see finding 1. Programs are cached per revision. `build_program` → `Err(mips)` goes to the engine thread (deduplicated per snapshot).
4. `composite(&programs, |h| store.try_get_hot(h))`: `Ready` / `Empty` recorded; `Deferred { missing }` → one rayon job per missing tile calls `store.get` (deduplicated), then wakes the render thread. The render thread never calls `TileStore::get`.
5. Plan again with this frame's results, draw with `ViewportRenderer` into the double-buffered `Rgba8Unorm` texture, submit through `wgpu_sync::Queue`, send `ViewportFrame`.
6. Another frame follows at once only if the plan is incomplete **and** this frame made progress (or spent its upload budget); otherwise the next frame comes from a loader wake or new mips — no busy loop while waiting on disk.

With no document open, the M0 test pattern of the virtual document is drawn as before.

### Findings (Claude-core APIs, not changed)
1. **Composite slots of tiles drawn from `ready` must be re-submitted every frame.** The compositor's slot clock reclaims any slot not used in the current frame, so a tile that is only *drawn* (not composited) could have its slot handed to another tile while still on screen. Re-submitting is a cache hit (key match, no GPU work) and cheap because programs are cached per revision. A `touch(slot)` API on `GpuCompositor` would make this even cheaper.
2. **`plan_frame` cannot express "ready but empty".** An `Empty` tile reported as not ready would be re-requested forever and keep the plan incomplete. Empty tiles are reported with a sentinel slot and their draws dropped before rendering.

## M1-T08 — documents (`documents.rs`, `engine.rs`, `fx-app`, `ui/js/native/documents.js`)

* `EngineInput::Open(Vec<PathBuf>)` (new variant). Each file is imported as a job on its own thread (import is rayon-parallel inside): `progress` messages (~1 % steps, import = 90 %, then "building previews" = the full mip pyramid via `ensure_all_mips`), `progress_done`, then the document appears. Errors → `error` message with the reason; cancelled → silent.
* A document = one "Background" pixel layer (position-locked, like Photoshop), its own `History` and its own `ViewState` (fitted to the shared viewport). `document_opened`, `active_document`, `layers` and `view` are sent; a page reload (`hello`) gets all of them again.
* `activate_document`, `close_document`, actions `tab:close` / `tab:close-all`. Closing drops the document and with it every tile handle (memory is freed by the store).
* Dirty mips requested by frames (after edits, M2) are computed on the engine thread with `ensure_mip` and committed without an undo step or revision bump; the snapshot is refreshed.
* The tile store: reference-machine budgets, scratch file in `%LOCALAPPDATA%/Fotox/scratch` (shell passes it to `EngineHandle::spawn`, a new parameter).
* **Shell:** `dlg:open` (menu, Ctrl+O) → native `rfd` dialog on a helper thread (TIFF, PNG, JPEG, All) → `Open`. Drag and drop (winit data transfer, file URIs → paths, UNC included) → `Open`. `fotox.exe FILE…` → `Open`.
* **UI (native):** tabs are created/updated/removed from engine messages (name, `@ zoom %`, `(RGB/8|16)`, tooltip with size/profile/ppi), click → `activate_document`, × → `close_document`; status bar shows import progress and the active document's size; the mock Open dialog is skipped in the app.

# M3-T04 — Save, Save As, compaction

Agent: Buffy (Codebuff)  ·  Branch: `task/M3-T04-save`  ·  Status: ready for review (library; engine wiring pending)

## Plan (written before coding)

1. `fx-io/src/fxd/save.rs`: `save`, `SaveTarget::{Incremental, Fresh}`,
   `SaveReport`, `needs_compaction`.
2. Walk every `TiledImage` (level 0 + derived ≥ 3), reuse a tile's chunk when
   it is already backed by this file, otherwise compress (zstd L1 incremental /
   L3 fresh) and append.
3. Manifest + preview, commit, then `attach_backing` for every written tile.
4. Tests: 0 tiles for an opacity change, exactly 1 for a painted tile,
   compaction shrinks + keeps pixels, an interrupted save opens the previous
   version.

## What was done

* `save(SaveRequest { doc, store, preview }, target, progress)` →
  `SavedFxd { file, report }`.
  * Incremental: `FxdWriter::append_to`, reuses the chunk of any tile whose
    `backing()` source is this file.
  * Fresh: writes `<target>.part`, `commit`s, drops the handle, `rename`s over
    the target, reopens it. All tiles are re-pointed with `attach_backing`.
  * `live_bytes = header + every referenced chunk + footer`; the footer stores
    it so compaction can compare it with the file length.
* `needs_compaction(live, file_len)` implements the 50 % rule; the background
  compaction job belongs to the engine (M3-T04 wiring).
* The flattened composite preview is rendered by the **caller** and passed as
  `SaveRequest::preview`; `fx-io` cannot depend on `fx-engine` (which depends
  on `fx-io`). `manifest::image_entry` was made public for this.
* Cancellation: `progress` returning `false` aborts before doing anything else.

* `fresh_then_incremental_reuses_every_tile`: first save writes 1 tile; after
  an opacity change the second save writes **0** tiles and reuses 1, and the
  reopened document carries the new opacity with identical pixels.
* `painting_one_tile_writes_exactly_that_tile`: after a paint, exactly 1
  level-0 tile is appended.
* `compaction_shrinks_the_file_and_keeps_every_pixel`: 20 manifest-only saves
  grow the file; a fresh save is smaller and its pixels round-trip.
* `a_truncated_last_save_opens_the_previous_version`: truncating the second
  save leaves the first manifest readable.

## Deviations from the task card

* Signature: `save` takes a `SaveRequest` (with an optional preview image)
  instead of `(doc, store, target, progress)`, because the preview must be
  rendered by the engine, not `fx-io`.
* It returns `SavedFxd` (the reopened file + report), because Save As must hand
  the new `Arc<FxdFile>` to the engine for `attach_backing`.
* "Copy tiles backed by another file without recompressing": not implemented —
  `TileSource::read` returns decompressed pixels, so reading raw chunk bytes
  would need a new trait method on the frozen `TileSource`. A Fresh save
  recompresses. Recorded as an open problem.
* Engine wiring (jobs, `OpenDoc.file/path`, dirty state, compaction background
  job, Save As to the document's own path) is M3-T06/T04 engine work and is not
  in this commit.

## Open problems / suggestions

* Add `TileSource::raw_chunk(offset, len) -> Option<&[u8]>` (default `None`)
  so Save As can copy compressed tiles verbatim; this changes a frozen trait,
  hence left out here.
* Compaction to the document's own open path needs the old handle dropped first
  (Windows refuses to replace an open file) and undo-only tiles copied to
  scratch — engine logic, part of the T06 wiring.

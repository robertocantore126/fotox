## Plan (written before coding)

1. `protocol.js` already has every message type and the framing (M0-T04).
2. `bridge.js` browser mode → `mock-engine.js`; replies take the same encode → decode path, asynchronously.
3. `main.js`: register `toast`/`error` handlers, then send `hello {ui_version}`.
4. `actions.js`: every action id is also sent as `{type:"action", id}`; local behaviour unchanged.
5. `popup.js` / `dialogs.js` emit an `overlays` event on every open/close; `main.js` turns it into `direct_input {enabled}` (sent only on change).
6. Shell `bridge.rs`: decode + route (shell vs engine), answer `hello` with `toast "Engine connected"` until the engine exists, log the rest at `debug`; `app.rs` keeps the `direct_input` flag for M0-T06.

The card says the mock answers every `action` with a toast, but that would add a toast to every tool click and panel toggle, and the card also requires the UI to "keep working exactly as before". Engine-owned actions (doc, image, layer, filter, …) get the "not implemented (mock engine)" toast.
2. Unimplemented engine actions show two toasts in the browser (the old local "mock" one and the engine's), which the card accepts ("remove the local mock toasts only when the engine handles them").

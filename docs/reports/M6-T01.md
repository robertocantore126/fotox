# M6-T01 — Resampling core (`fx-ops::resample`)

Agent: Buffy  ·  Branch: `m6` (see "Deviations")  ·  Status: ready for review

## Plan (written before coding)

1. `fx-core/src/transform.rs`: the serialisable *parameters* — `Filter`
   (D-052), `Mapping` (`Affine` / `Projective` / `Warp(BezierPatch)`),
   `BezierPatch`. They live here because `Command::Transform` (M6-T04) must
   serialise them and `fx-core` cannot depend on `fx-ops` (recipe R1a, the
   `FilterParams` precedent).
2. `fx-ops/src/resample/kernels.rs`: `keys(x, a)`, `mitchell(x)`,
   `lanczos3(x)`, the linear kernel, and the tap/weight builder over one axis
   (`base = floor(u − 0.5)`, taps `base − s + 1 ..= base + s`, SNIPPETS §11).
3. `fx-ops/src/resample/mapping.rs`: `inverse_point`, `scale_at` (largest
   singular value of the destination→source Jacobian, the minification measure
   of SNIPPETS §10) and `source_bounds` of a destination rectangle, for all
   three variants.
4. `fx-ops/src/resample/warp.rs`: the 4 × 4 Bézier patch's triangle mesh — the
   patch forward-mapped onto a 64 × 64 grid of quads, split into triangles
   holding their `(u, v)`; per tile the triangles whose destination box touches
   it; per pixel the barycentric coordinates give `(u, v)` → source point. Last
   triangle wins on fold-overs.
5. `fx-ops/src/resample/mod.rs`: `resample(...)` — one destination tile at a
   time on rayon, source tiles fetched once per tile, minification by reading a
   mip level chosen from `scale_at`, premultiplied sampling, un-premultiply
   after clamping `0..=a`.
6. Tests (the card's list) on a `LevelSource` over a whole-image test fixture,
   including across tile seams and 8-/16-bit.

## What was done

Everything in the plan, plus the card's exact-case shortcut.

* **`fx-core::transform`** — `Filter` (with `label`, `resolve(scale)` for
  Bicubic Automatic, `support`, `is_interpolating`), `Mapping` (adjacently
  tagged serde: `{"kind": "affine", "value": [...]}`,
  `identity`/`affine`/`translation`/`scale`/`rotation_about`, `is_finite`,
  `integer_translation`), `BezierPatch` (`identity`, `rect`, `set_point`).
* **`fx-ops::resample::kernels`** — the five kernels and the normalised tap
  builder. Verified: interpolating kernels are exact at a pixel centre, the tap
  set is symmetric at a half-pixel, and weights sum to 1 everywhere in
  `u ∈ [−3, 6.2]`.
* **`fx-ops::resample::mapping`** — `Transform` prepares a mapping once
  (building the warp mesh) and answers `inverse_point`, `scale_at` (analytic
  for affine, central difference for projective/warp), `source_bounds` and
  `candidates`.
* **`fx-ops::resample::warp`** — `evaluate` (bicubic Bernstein), `WarpGrid`
  (64 × 64 → 8192 triangles) with `intersecting`, `Triangle::barycentric` and
  `parameter_at` (last triangle wins).
* **`fx-ops::resample`** — `resample(src, SourceInfo, mapping, filter, level,
  dst_tiles)`. The local scale picks the concrete filter and the source mip
  level; the source box (destination tile corners mapped back, grown by the
  kernel support) loads only the tiles it needs; sampling is premultiplied with
  the `0..=a` clamp. **Exact shortcut:** a whole-pixel translation at level 0
  is a pixel copy (`copy_tile`), for every filter.

## Deviations from the task card

1. **Where the parameter types live.** The card lists `mapping.rs`/`warp.rs`
   under `fx-ops::resample`. The *data* types (`Filter`, `Mapping`,
   `BezierPatch`) are in `fx-core::transform` instead, because
   `Command::Transform` (T04) has to serialise them and `fx-core` cannot depend
   on `fx-ops`. `fx-ops/resample/mapping.rs` and `warp.rs` hold the
   **algorithms** on those types, exactly as the card lists them. This is the
   `FilterParams` split (recipe R1a) already used in the code base.
2. **`resample`'s signature.** Instead of
   `(src: &TiledImage, src_offset, store, …, level_scale, dst_tiles)` it is
   `(src: &dyn LevelSource, SourceInfo { size, levels }, mapping, filter, level,
   dst_tiles)`. Reason: `fx-ops` cannot call the engine's `ensure_mip`, so the
   sampler must read through the same level-aware `LevelSource` the filters use
   and the engine makes the mip levels valid first (R1a/R8). `level` (the
   destination mip) replaces the card's `level_scale`, which was otherwise
   ambiguous about which level the *source* mip choice is relative to.
3. **Bicubic Smoother is approximating.** Mitchell–Netravali has an 8/9 centre
   tap, so a 1:1 resample with it is a mild blur — mathematically inherent to a
   smoothing kernel and Photoshop's behaviour for that filter too. The card's
   "identity mapping = exact copy" therefore holds via the **exact shortcut**
   (an integer translation is a pixel copy), which is also the card's "an
   integer translation = `OffsetLayer` (no resampling)". The interpolating
   kernels are additionally exact on their own.
4. **Gray formats are refused.** `resample` returns an error for Gray sources,
   like the filters do ("filters run on RGBA layers"). Image Size must resample
   masks; that is added in T02 with the mask path, not here.

## Open problems / suggestions

- **`resample` returns a `Vec` of tiles bounded by `dst_tiles`.** This is safe
  for a preview (a screen's worth of tiles) but a whole-document commit must
  not collect 13 736 buffers at once — the engine wrapper (T02/T04) has to
  commit in batches, exactly as `filters.rs` does (`BATCH = 8`). Worth a shared
  helper so no future caller repeats the pattern the deep review flagged
  (`docs/reviews/2026-09-25-deep-code-review.md`, S1-01). Not this card's
  scope.
- **Warp quality at strong distortion**: the 64 × 64 mesh is the approximation
  of the patch. A future `segments` parameter (or a finer mesh near handles)
  is a local change in `warp.rs`.
- The card's "quarter-turn rotations and flips = pixel permutations" belongs to
  T02 (`fx-ops::permute`), not here.

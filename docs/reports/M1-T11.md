# M1-T11 — Frame-time overlay and memory readout

Agent: Claude  ·  Branch: `task/M1-T11-overlay`  ·  Status: done, not yet seen in the app (Rob tests)

## What was done

* **Render statistics** (`fx-engine/src/stats.rs`): the render thread records each frame's duration (start of frame work → submit) and finish time; the engine summarises the last 2 s as fps and p50/p99 frame time. Also: source tiles uploaded by the last frame (delta of the compositor's counter) and tiles being loaded from warm/cold storage.
* **`status` message** every 500 ms from the engine thread: memory (tiles in RAM = hot, compressed = warm, scratch file = cold bytes, GPU = the compositor's up-front allocation: atlas budget + composite cache) plus the frame statistics. `EngineToUi::Status` gained `frame_ms_p50`, `frame_ms_p99`, `uploads`, `pending_loads` (`#[serde(default)]`); `docs/PROTOCOL.md` updated in the same commit.
* **Overlay** (`debug:fps`, **Ctrl+Alt+F**): a small monospace panel in the top-left corner of the viewport (HTML over the viewport hole, `pointer-events: none`): fps, p50/p99 ms, uploads, loading. In a browser the action explains it needs the app.
* **Status bar**: the old mock "8.4 MB" item shows `RAM x GB` (hot + warm) with a tooltip splitting RAM / compressed / scratch / GPU.
* `debug:` joined the UI-local action prefixes (Rust and the JS mock), so it never gets a "not implemented" toast.
* `engine::run` takes an `EngineContext` (clippy: too many arguments).

## Notes

* Frames are drawn only when something changes, so an idle view shows 0 fps; the numbers mean something while panning/zooming (S2).
* The frame time is render-thread time, not present-to-present; for the S2 "no frame > 33 ms" check, PresentMon remains the reference.

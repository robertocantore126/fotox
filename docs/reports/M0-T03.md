# M0-T03 — Shell: window + CEF + Fotox UI

Agent: Buffy (Freebuff)  ·  Branch: `task/M0-T03-shell`  ·  Status: ready for review

## Plan (written before coding)

1. `main.rs`: `UiContext::setup()` first (CEF helper processes re-enter `main`
   and must exit immediately), then logging, single-instance lock
   (`%APPDATA%/Fotox/instance.lock`), wgpu context, winit event loop,
   `UiContext::start`, `ui_context.instance(&device, &queue)`, `ui-events`
   bridge thread, restart-on-acceleration-failure. Port of `lib.rs` with the
   `wrapper::*` editor pipeline removed (`docs/GRAPHITE.md` §2: our bridge is
   `fx-protocol`, which arrives in M0-T05).
2. `gpu.rs`: instance/adapter/device/queue through `wgpu_sync` so the queue is a
   `wgpu_sync::Queue` (pattern from `crates/fx-render/src/gpu/tests.rs::gpu()`);
   DX12 preferred, `FOTOX_WGPU_ADAPTER` override, adapter listing.
3. `window.rs` + `window/win.rs` + `window/win/native_handle.rs`: keep the
   `cfg`-per-platform structure; Windows init = AppUserModelID, COM apartment,
   console attach. Window is **frameless**, because the Fotox UI draws its own
   title bar (`ui/css/app.css` `.topbar` / `.brand` with `app-region: drag`).
4. `render.rs` + `composite.wgsl`: port the composite pass — surface config,
   1 × 1 transparent fallback texture for the viewport (T04 binds the real one),
   viewport offset/scale immediates, background `#282828`, UI texture on top.
   Drop the Vello overlay stage and Graphite's `WgpuExecutor`
   (`docs/GRAPHITE.md` §2 says drop both).
5. `input.rs`: simplified port. With `direct_input` false every pointer event is
   `Route::Ui`, so the UI/editor split, viewport-rect test and tablet state all
   collapse away and the table of winit → `InputEvent` conversions (plus
   multi-click tracking and modifier tracking) is what remains. The routing
   machinery arrives with M0-T06.
6. `app.rs`: `ApplicationHandler` — create window and render state, resize and
   scale forwarding (`UiCommand::Resized` / `ScaleChanged` / `Refresh`), bind
   `UiEvent::Frame`, apply `UiEvent::Cursor`, redraw on wake, exit on close, and
   the 3-second accelerated-UI watchdog that restarts with acceleration off.
7. `cli.rs`, `consts.rs`, `dirs.rs`, `preferences.rs`, `event.rs`: small helpers.
   Preferences as JSON (`serde_json`, already approved) instead of RON.
8. New dependencies: `dirs` (app data dir). `fd-lock` is **not** needed —
   `std::fs::File::try_lock()` is stable and verified working on this toolchain.
   Record both facts in `docs/DECISIONS.md`.
9. Verify: `cargo xtask run` opens in < 3 s showing the Fotox UI, menus and
   dialogs work, resize and 100/125/150 % scaling stay sharp, closing leaves no
   `fotox.exe`, `GRAPHITE_BROWSER_DEBUG_PORT=9222` is inspectable.

> Point 8 of the plan was wrong and is corrected in *Deviations*: `File::try_lock`
> is stable since Rust 1.89 while `workspace.rust-version` is 1.88, so clippy
> rejects it and `fd-lock` is used.

## What was done

The app now opens a window showing the Fotox UI, rendered by CEF off-screen,
composited over a wgpu viewport by one full-screen pass.

**Entry point (`main.rs`).** `UiContext::setup()` runs before logging so CEF
helper processes exit without starting an editor. Then: logging, the
single-instance lock, `App::init()`, the event loop, the GPU context, the UI
start, the `ui-events` bridge thread, and the event loop itself. Graphite's
`DesktopWrapper` pipeline is gone; `event.rs` carries what it carried, and
`UiEvent::Message` is logged instead of decoded until the M0-T05 bridge.

**Two ordering/discovery findings that changed the design**

* *The event loop must come before the GPU context.* The first working build
  failed at `create surface: No 'DisplayHandle' is available to create this
  surface with. When creating a surface with 'create_surface()' you must specify
  a display handle in 'InstanceDescriptor::display'.* The card lists the wgpu
  device before the winit event loop, but the instance has to be built from
  `EventLoop::owned_display_handle()`. The reference got away with the other
  order only because its wrapper owned the instance.
* *The composite pass needs `Features::IMMEDIATES`.* `set_immediates` requires
  the feature, and the `gpu()` pattern the card points at (`required_limits:
  limits`, default features) does not request it. The device now requests
  `IMMEDIATES` and fails with a named error on an adapter that lacks it.

**Adapter selection.** DX12 only (decision D-003), enumerated with every adapter
logged so a `FOTOX_WGPU_ADAPTER` index is actionable; without an override a
discrete GPU is preferred. On the reference machine: adapter 0 = NVIDIA GeForce
RTX 3060 (`Dx12, DiscreteGpu`), adapter 1 = Microsoft Basic Render Driver
(`Cpu`).

**Window.** Frameless (`with_decorations(false)`), 1600 × 1000, minimum
1024 × 700, so the UI's own `.topbar` acts as the title bar. `window/win.rs`
does the Windows init the reference does (console attach, COM apartment,
AppUserModelID); the mac/linux modules are not ported, per `GRAPHITE.md` §2.

**Render.** Surface configuration, `composite.wgsl` (ported verbatim), a
`Immediates` block whose `_pad` field exists because `background_color`'s `vec4`
alignment pushes it to offset 32, `#282828` background, and the reference's
"UI texture is the wrong size, present it stretched once and ask the UI to
re-render" behaviour. Resize is applied on the next presented frame rather than
immediately, so a resize cannot reconfigure the surface under a frame in flight.

**Input.** Every winit event is converted and forwarded as
`UiCommand::Input`. Modifier state and per-button multi-click counting are
tracked, because the UI needs a click's count to open the right menu level.

**The single-instance lock needed a second attempt.** The first version took the
lock in a helper returning the `RwLock`, and a second instance launched happily:
fd-lock's lock is owned by the *guard*, so dropping the guard when the helper
returned released the lock. The guard borrows the `RwLock`, so both must be
locals of the same function; they are now locals of `run()`.

## Deviations from the task card

1. **`window/win/native_handle.rs` was not ported.** In the reference it is a
   418-line custom frameless window frame: an invisible helper window that
   hit-tests the resize borders and is subclassed onto the main window, all of
   it `unsafe` Win32. `docs/GRAPHITE.md` §2 says to keep "Windows init
   (AppUserModelID, COM, console attach), native handle helpers", which is what
   `window/win.rs` does, and to drop the mac/linux files; it does not ask for
   the frame. M0-T03's acceptance says nothing about resize borders, shadows or
   a frameless frame, and nothing in `docs/` describes Fotox's window chrome.
   The window is frameless (the UI's `.brand` is a drag region) but relies on
   winit rather than a resize ring, so **it currently has no native resize
   border and no custom shadow.** Porting the helper window is a task of its own
   and I did not want to add ~400 lines of `unsafe` that the card does not ask
   for. Please rule on this.
2. **New dependencies are `dirs` and `fd-lock`**, not `dirs` alone. `File::try_lock`
   is stable since 1.89 but `workspace.rust-version` is 1.88, so
   `cargo clippy -D warnings` fails it as `clippy::incompatible_msrv`. Recorded
   as D-021. Raising the MSRV would have been a workspace-wide decision.
3. **The event loop is created before the GPU context**, not after as the card's
   step 1 lists, because the instance needs the event loop's display handle
   (see *What was done*). `App::init()` still runs before either.
4. **Preferences are JSON, not RON**, to avoid a third new dependency.
   `serde_json` was already approved.
5. **Adapter selection enumerates adapters and prefers a discrete GPU** rather
   than calling `request_adapter`, so the index printed at startup is the index
   `FOTOX_WGPU_ADAPTER` accepts.
6. **Vello is not used**, per `GRAPHITE.md` §2; the overlay texture slot is bound
   to the transparent texture until M0-T06 renders overlays into the viewport.
7. **`persist.rs` and `socket.rs` were not ported** (they are not in the card's
   port list). A second launch therefore does not hand its file arguments to the
   running instance; the reference's `socket::send` path is absent.
8. **`ctrlc` was not added.** Ctrl-C in a terminal kills the app without running
   `ui.shutdown()`; the reference installs a handler for that.

## Open problems / suggestions

1. **The UI's top bar cannot drag the window yet.** `ui/css/app.css` marks
   `.brand` with `app-region: drag`, and Chromium does not implement that in
   windowless/off-screen mode — the reference handles it by having the UI send a
   `WindowDrag` frontend message and calling `winit`'s `drag_window()`. That
   message is part of Graphite's protocol, which Fotox replaces with
   `fx-protocol` in M0-T05. Until then the window cannot be moved by its own
   title bar. Worth adding a message for it to `fx-protocol` early in M0-T05.
2. **The accelerated-UI watchdog cannot fire yet.** It requires
   `web_communication_initialized`, which needs `UiEvent::Ready`, which needs the
   page to call `window.initializeNativeCommunication()` — M0-T04 step 2. So the
   `--disable-ui-acceleration` path and the automatic restart are implemented but
   only exercised by the flag today. Worth re-verifying in M0-T04.
3. **Resize and per-monitor scaling are the unverified part of the acceptance.**
   The logic is there and the stretch-then-refresh path is exercised on every
   startup, but dragging between a 100 % and a 150 % monitor is a manual check
   with no automation here. Since the card's acceptance calls it out explicitly,
   it should be done before M0's checklist is ticked.
4. **`RUST_LOG` needs the crate name `fotox`, not `fx_app`.** The binary's crate
   name comes from `[[bin]] name`, so the module path in log filters is `fotox`
   while the package is `fx-app`. `AGENTS.md` §7 suggests
   `RUST_LOG=fx_engine=debug,fx_app=debug`, which silently enables nothing for
   this crate. Worth correcting there (and in whatever M0-T06 adds).
5. **`cargo fmt`'s package list still does not include `tools/xtask`** (raised in
   M0-T02); this task added `-p xtask` by hand again.
6. The window is frameless with no native resize border (deviation 1). Until
   that is settled, resizing only works from the window's edges as winit allows,
   which is noticeably worse than the reference's helper-window ring.

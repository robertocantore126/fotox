# M3-T05 — Open (lazy)

Agent: Buffy (Codebuff)  ·  Branch: `task/M3-T05-open`  ·  Status: ready for review (library; engine/UI wiring pending)

## Plan (written before coding)

1. `fx-io/src/fxd/open.rs`: `open(path, store) -> OpenedFxd { document, file,
   preview, manifest }` — footer → manifest → backed document.
2. Expose `manifest::image_from_entry` so the opener rebuilds the preview the
   same way it rebuilds layer/mask images.
3. Tests: opening a 220-layer file reads no tile; open → edit → save → open
   equals the edited document; the composite preview round-trips.

## What was done

* `fxd::open::open` reads only the footer and the manifest chunk (checksum
  verified), decodes the manifest, builds the document with `from_manifest`
  (every tile backed, nothing read) and rebuilds the stored composite preview.
* `sniff` already recognises `FOTOXFXD` (T01); `import_file` refuses `.fxd`
  with a pointer to this opener.
* Engine/UI wiring (create the `OpenDoc` with `file`/`path`, use the preview as
  the coverage level in `plan_frame`, and the `.fxd` drag-drop filter) is M3-T05
  card work in `fx-engine`/`fx-app` and is not in this commit.

* `open_reads_only_the_manifest`: a 220-layer file opens; `backed_reads` and
  `hot_bytes` are unchanged (no tile is read or warmed); reading one layer's
  tile afterwards reads exactly one chunk from the file.
* `open_edit_save_open_equals_the_edited_document`: open → change opacity +
  paint a tile → incremental save → reopen gives the edited document back.
* `the_composite_preview_round_trips`: a level-3 preview saved with the
  document is rebuilt on open.

## Deviations from the task card

* The card measures "reads < 1 % of its bytes before the first frame". The test
  asserts the stronger, exact property that **no** tile is read on open (only
  the manifest), which is what the 1 % bound expressed for a backed document.
* `OpenedFxd` also carries the decoded `Manifest` for diagnostics; the card
  only names the document, file and preview.

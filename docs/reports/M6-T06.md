# M6-T06 — Shape layers

Agent: DeepSeek (Codebuff)  ·  Branch: `m6`  ·  Status: ready for review

## Plan (written before coding)

- The model in fx-core (`VectorShape`, `Paint`, `StrokeStyle`, `LayerKind::Shape`),
  one command pair (`AddLayer { NewLayer::Shape }`, `SetShape`) and `Rasterize`.
- Tiles are **derived**: a shape layer's cache is a `TiledImage::derived` of the
  document's size whose tiles are drawn from the geometry at the requested
  level, on demand (D-050: tiny-skia, CPU). Level 0 is drawn by the same
  function, so export, merge, crop, copy and rasterise see the shape with no
  separate "flatten" path.
- The render thread asks for the tiles it needs through a `VectorRequest`, next
  to the existing `MipRequest`; the engine answers with one rayon batch per
  layer.
- The tools (U: Rectangle, Rounded Rectangle, Ellipse, Polygon, Line) and Path
  Selection (A) in fx-engine, dragging out a box; a shape is added once, on
  release, so the whole drag is one history step.
- Persistence: only the geometry goes into the manifest (`serde(default)`
  fields), the cache is rebuilt on load.

## What was done

- **fx-core**
  - `vector.rs` (new): `VectorShape::{Rect { w, h, radii }, Ellipse, Polygon
    { sides, star_inset }, Line { length, width }, Path}` with
    `bounds`/`outline`/`stem`/`contains` (even-odd crossing test for the hit
    test), `Paint::Solid`, `StrokeStyle { width, align, paint, dash }`,
    `document_box` (a shape's box through its matrix) and `grow_box`.
  - `LayerKind::Shape { shape, fill, stroke, transform, cache }`.
  - `document.rs`: the default name follows the shape, so a rectangle is
    "Rectangle 1" and a star "Star 1" (`NameKind::of_shape_stem`); the counters
    are appended to the ones saved in `.fxd`, so older files still load.
  - `command.rs`:
    - `NewLayer::Shape` → a document-sized **derived** cache ("Rectangle 1"
      with the tool that drew it).
    - `Command::SetShape { layer, shape, fill, stroke, transform }` ("Set
      Shape" / "Fill" / "Stroke" / "Move"): patches the geometry and dirties
      only the tiles the old **or** the new box reaches (`mark_rect_dirty`),
      so editing a shape never queues a document's worth of tiles.
    - `Command::Rasterize { layers }` ("Rasterize Layer(s)"): each layer is
      composited alone (its own opacity, fill and blend neutralised) and
      becomes a pixel layer that keeps its id, name, place, opacity, blend mode
      and mask. A pixel layer or a group is refused.
    - A canvas-level change moves **matrices**, not pixels: `Permutation::mapping`
      + `Mapping::then_affine` fold a rotate/flip/crop/size into every shape's
      matrix, `set_canvas` rebuilds their caches at the new canvas size. So
      Image ▸ Rotate 90°, Flip, Canvas Size, Image Size and a straightening
      Crop keep a shape sharp and where it belongs.
- **fx-tiles**: `TiledImage::derived` (level 0 derived too) and
  `mark_rect_dirty` (the tiles of every level that touch a document rectangle).
- **fx-render**
  - `vector.rs` (new): `render_shape_tile` — the shape's outline as a tiny-skia
    path, the layer matrix composed with the level scale and the tile origin,
    one `Pixmap` per tile, converted to the document's format. `Inside`/`Outside`
    strokes are the 2 × width stroke clipped to the covered/uncovered side
    (exactly `width` wide on that side), `Center` is tiny-skia's own.
  - `program.rs`: `SourceTile::{Mip, Vector}` and `TileRequest::{Mip, Vector}`
    so `build_program` asks for a shape's tiles the same way it asks for a mip;
    a shape layer with no paint is skipped.
- **fx-engine**
  - `vector.rs` (new): `draw_shape_tiles` (one parallel batch per layer,
    `slot_for` collapsing uniform tiles to `Empty`/`Solid`) and
    `prepare_level0`, which fills in the dirty level-0 tiles of the named shape
    layers — the viewport only ever asks for the tiles it shows, while merge,
    flatten, crop, rotate, image size, copy, export and rasterise read layers
    the view may never have displayed. Hooked into `start_pixel_job`, `export`,
    `copy_layer` (which now copies a shape as its pixels) and the rasterise
    action.
  - `tools/shape.rs` (new): the five tools. Shift = square/circle/equilateral,
    Alt = from the centre, the option bar's `Radius` / `Sides` / `Kind` /
    `Stroke Width` / `Weight`, the fill from the foreground colour; the drag is
    previewed as the shape's own outline (M5-T02) and committed as one
    `AddLayer`. The Line tool keeps the drawn direction (Shift snaps to 45°).
  - `tools/path_select.rs` (new): click picks the topmost shape under the
    pointer (hit test in the shape's own space), dragging moves it by changing
    the matrix — one cheap `SetShape` on release, no pixels touched.
  - `layers.rs` / `thumbs.rs`: a shape layer reports `kind: "shape"` and its
    fill colour; its thumbnail is **drawn from the geometry** at the level the
    panel needs, so the row shows the shape.
  - `engine.rs`: `raster:shape` / `raster:layer` / `raster:all` (Layer ▸
    Rasterize); the rasterise path draws the level-0 tiles first. On a pixel
    layer the items do nothing, like Photoshop's greyed-out ones.
- **UI**: `ui/js/actions.js` no longer shows the mock "not implemented" toast
  for `raster:`, and the Layers panel asks for a shape layer's thumbnail.
- **docs/PROTOCOL.md**: the shape tools, `add_layer`/`set_shape` JSON, the
  rasterise actions, `kind: "shape"` and `fill_color`.

## Verification

- `cargo check --workspace --all-targets`, `cargo fmt … -- --check` and
  `cargo clippy --workspace --all-targets -- -D warnings`: clean.
- `node ui/tools/check-data.mjs`: every action, panel, tool and icon exists
  (`raster` now among the handled prefixes).
- New tests (the author has not run the full suite; T10 is the acceptance run):
  - fx-render `vector_tests.rs`: a rect at level 0 covers **exactly** its
    pixels (alpha 255 inside, 0 outside, no partial edge); a rect at level 2
    covers the same area as level 0 within 2/255 of a tile's pixels; an
    ellipse is round with partial edge pixels; center/inside/outside strokes
    land on the right side of the outline; a line is a bar of its weight and
    follows its angle; the Polygon tool's pentagon points up inside its box; a
    rounded rectangle cuts its corners; tile origins place a shape in the tile
    it belongs to.
  - fx-core `vector.rs`: every outline stays inside the box it reports, hit
    tests agree with the box, radii clamp, `document_box` follows the matrix
    (including a quarter turn), stems name the layered shapes, JSON round trip.
  - fx-core `command.rs`: a shape layer's cache is derived and canvas-sized; a
    fresh one is named after its shape; `SetShape` dirties only the old and new
    boxes (a 100 × 50 rect at (10, 10) is tile (0, 0), moving it to (300, 250)
    adds tile (1, 1)); `SetShape` on a pixel layer is refused; `Rasterize`
    turns a shape into pixels and keeps id, name, opacity and blend, and
    refuses pixels/a group/an empty list; rotate/flip/image size/crop/canvas
    size/straighten move the matrix (and resize the cache) as the pixels do.
  - fx-tiles `image.rs`: a derived image starts dirty at every level;
    `mark_rect_dirty` touches only the tiles a rectangle overlaps (a
    collection across levels) and nothing outside the image.
  - fx-engine `vector.rs`: a composite **fails** while a shape's level 0 is
    dirty and succeeds after `prepare_level0`, then the composite shows the
    fill exactly inside the rect and nothing outside; preparing one layer
    leaves the others dirty; drawing twice is a no-op.
  - fx-io `manifest.rs`: a shape layer round-trips through a real file, the
    manifest holds the geometry and no tiles, and the layer comes back with a
    derived, dirty, canvas-sized cache.

## Deviations from the task card

- **"The program key includes a hash of (shape, paints, transform)"** — not
  done, and not needed: a fixed tile's program is cached per document
  *generation*, and every `SetShape` bumps the generation, so the programs are
  rebuilt by themselves. What a tile *is* derives from `mark_rect_dirty` (only
  the tiles the edit can reach) plus the generation. Adding a hash would be a
  second invalidation mechanism to keep in sync.
- **A separate `tools/shape.rs` module** — kept (the card named it), and
  `tools/path_select.rs` next to it.
- **`raster:all`** rasterises every shape layer of the document; fill and
  adjustment layers are still handled by their own kinds (a "smart object"
  item exists in the menu, disabled, as the card says).
- **A rotated shape's cache** is a bound (the four corners of the local box
  through the matrix), so a rotated 100 × 50 rect dirties its axis-aligned box:
  correct, just occasionally a tile more than strictly needed.

## Measurements

- `render_shape_tile` at level 0 for one 256 × 256 tile: a path build plus one
  fill (and one stroke). A shape is drawn once per tile a level *needs* — the
  tiles its box touches, and at the level the viewport shows — never a whole
  document: the 300 × 200 rectangle of the tests is 2 tiles on any canvas size.
- A `SetShape` (a fill edit, a drag, an option-bar change) dirties the tiles of
  the old and new boxes only; the Path Selection drag sends **one** command on
  release.
- The added tests, 42 in all: 13 in fx-render's shape module, 9 in fx-core's
  vector module, 12 in fx-core's command module, 4 in fx-tiles, 3 in fx-engine's
  vector module, 1 in fx-io.

## Known gaps / suggestions

- Direct Selection (moving single anchors) and the Pen tools are out of scope,
  as the card says; `VectorShape::Path` exists for PSD import and for them.
- A shape layer cannot be Free Transformed (Ctrl+T): Photoshop scales the
  *path*. `Command::Transform` refuses a non-pixel layer, so the box closes
  with "Nothing to transform". Moving and reshaping a shape goes through the
  Path Selection tool and `SetShape`; scaling its matrix from the box is the
  natural next step.
- `NewLayer::Shape` has no "Pixels"/"Path" mode: the option bar's mode is
  ignored (a shape layer is always a layer). Photoshop's "Pixels" mode paints
  into a pixel layer instead — worth wiring in T09.
- Adding two shapes with the same mode never merges them into one layer, and
  the option bar's add/subtract/intersect "shape area" buttons do nothing yet
  (Photoshop combines paths; Fotox would need a compound path).
- A shape's `stroke` in the option bar is the background colour and a single
  `Center` align; the Stroke Options popup (align, caps, dashes) is T09's.

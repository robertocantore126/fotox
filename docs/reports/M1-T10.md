## What was done

`fotox-cli bench <scenario> [--file F] [--csv PATH]` (`src/bench.rs`). Each run appends rows to `bench/results.csv` (default, `--csv` overrides) as `date,commit,scenario,document,metric,value,unit,notes`, with `git rev-parse --short HEAD` and the UTC date; CSV fields are quoted when needed.

| Scenario | What it measures | Rows |
| --- | --- | --- |
| `import --file F` | S1 engine part: raw sequential read of F (8 MiB reads), then `import_file` into a reference-budget store | `raw_read`, `import` (MB/s of file), `import_seconds`, `import_vs_raw` (%, target ≥ 80) |
| `trim` | 512 photo-like Rgba16 tiles (256 MiB, `gen`'s content function) inserted hot, `trim()` into warm (LZ4), then `get` of all | `lz4_compress`, `lz4_decompress` (MB/s) |
| `scratch` | same tiles, both RAM tiers tiny: `trim()` spills to the scratch file, then read-back tile by tile | `spill`, `read_back` (MB/s) |
| `mips [--file F]` | `ensure_all_mips` on F's image (or a generated 8192² image) | `full_pyramid` (s), target ≤ 10 s on B1 |

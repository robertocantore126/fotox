# M1 — Open and navigate

Goal: open a 30 000 × 30 000 16-bit TIFF and navigate it smoothly, with RAM
under budget. One layer, no editing.

Exit criteria: S1, S2, S8 in `docs/PERFORMANCE.md` §4, measured and recorded.

Read first: `docs/ARCHITECTURE.md` §3–4, `docs/PERFORMANCE.md`, the doc
comments in `crates/fx-tiles/src/*.rs` and `crates/fx-render/src/*.rs`.

tiers (T03, T04), the GPU atlas (T06), and in `fx-render` the tile programs,
the GPU compositor, the frame planner and the viewport pass used by T07.
Read `docs/reports/CLAUDE-core.md` first.

Spec tests already exist for several tasks, marked
`#[ignore = "M1-Txx"]`. Implementing a task includes removing its `ignore`

## M1-T01 — `fotox-cli gen` and `info`

**Goal** Deterministic benchmark images B1 and B2 (`PERFORMANCE.md` §3).

**Files** `crates/fx-cli/src/{main.rs,gen.rs,info.rs}`, `crates/fx-cli/Cargo.toml` (+ `tiff`, `rayon`).

**Spec**
* `fotox-cli gen OUT.tif --width W --height H --bits 8|16 [--seed N]`
* RGB, no alpha, uncompressed strips of 256 rows, **BigTIFF** when the file
  exceeds 4 GiB (always for B1). If the `tiff` crate cannot stream-write
  BigTIFF strips, write a minimal BigTIFF writer by hand (uncompressed
  strips are ~150 lines) — say so in the report.
* Content, per pixel, from `(x, y, seed)` only (so bands can be generated in
  parallel and results are identical run to run): large smooth gradients +
  4-octave value noise (period 4096…512 px) + per-pixel grain (±1.5 % for
  16-bit). It must look photo-like and **not** compress well — this is
  deliberate.
* Generate band by band (256 rows) in parallel with rayon, write
  sequentially. Memory: ≤ 4 bands in flight.
* Print progress and final throughput (MB/s).
* `fotox-cli info FILE`: size, bits, channels, compression, strip/tile
  layout, BigTIFF yes/no, ICC profile present.

**Acceptance** B1 is generated in < 2 min on the reference machine; two runs
with the same seed produce byte-identical files (compare SHA-256); peak RSS
< 500 MB.

## M1-T02 — Streaming TIFF import

**Files** `crates/fx-io/src/{lib.rs,tiff.rs}`, `Cargo.toml` (+ `tiff`, `rayon`).

**Spec**
* `import_file` sniffs the header (`II*\0`, `MM\0*`, `II+\0`, `MM\0+`).
* Supported: 8/16-bit; RGB, RGBA (straight or associated alpha → convert to
  straight), Gray, Gray+alpha; strips or tiles; none/LZW/Deflate/PackBits;
  classic and BigTIFF. Everything else → `IoError::Unsupported("…")` with a
  clear reason.
* Band pipeline: decode 256 rows (strips) or one row of tiles, convert to
  RGBA of the document depth, cut into 256² tiles, `TiledImage::put_buffer`.
  Decoding and tile conversion of different bands run in parallel (rayon);
  inserts happen in order. Memory ≤ 4 bands.
* ICC profile embedded → `ColorProfile::Icc(bytes)`; none → `Srgb`.
  Resolution tags → `ppi` (default 72).
* Progress callback per band; returning `false` cancels (partial tiles are
  dropped with the `TiledImage`).
* Tests: small generated TIFFs covering each supported variant (write them
  with the `tiff` encoder in the test), pixel-exact comparison of a few
  tiles, including the right/bottom edge tiles (outside pixels must be
  transparent).

**Acceptance** Importing B1 reaches ≥ 80 % of the raw sequential read speed
of the file (measure raw speed by reading the file into `/dev/null`
equivalent, report both). Peak RSS stays under the hot+warm budget (needs
T03/T04 for the full B1; until then test with a 15 000² file).

## M1-T05 — Mip generation

**Files** `crates/fx-tiles/src/mip.rs`, `crates/fx-engine/src/mips.rs`.

**Spec**
* Implement `downsample_2x2` as documented; the four `M1-T05` tests pass.
* Resolving children: `Empty` slot or outside the grid → `ChildPixels::Empty`;
  if all four children are `Empty` the parent is `Empty`, if all four are
  the same `Solid` the parent is that `Solid` (no pixel work).
* `fx-engine::mips`: `ensure_mip(image, level, tx, ty)` computes a dirty
  tile recursively from dirty children, on the rayon pool, inserting results
  as `TileClass::Derived` with `TiledImage::set_derived_slot`. If `get` of a
  derived child returns `Evicted`, recompute it.
* The compositor side tells you what is needed: `fx_render::build_program`
  returns `Err(Vec<MipRequest>)` listing the dirty mip tiles (layer, mask or
  not, level, x, y) a program needs. Compute exactly those first; then, at
  idle priority, the rest of the pyramid (level 1, 2, … in order).
* Mips are computed on a *copy* of the document's `TiledImage`s held by the
  engine thread, then committed to the document (they are derived data:
  committing them does not create an undo step and does not bump
  `Document::revision`).

**Acceptance** Tests above; `fotox-cli bench mips` on B1 (T10): full
pyramid in ≤ 10 s.

## M1-T07 — Render loop integration

Everything the render thread needs exists in `fx-render` and is tested
(`gpu/tests.rs` runs on a software Vulkan driver too). Your job is to wire it
into the engine's render thread.

**Files** `crates/fx-engine/src/render.rs`.

**Per frame** (only when something changed or work is pending):
1. `compositor.begin_frame()`.
2. `plan = fx_render::plan_frame(&view, viewport, doc.width, doc.height,
   level_count, &|key| ready.get(&key))` — `ready` is the map of tiles the
   compositor returned as `Ready` for the **current document revision**
   (clear it when the snapshot changes; the compositor's own key cache makes
   re-requests of unchanged tiles free).
3. For each `plan.requests` (already in priority order, cap ~256 per frame):
   `fx_render::build_program(&doc, level, tx, ty, &mut |a| luts.get(a))`
   (`luts: fx_render::adjust::LutCache`, owned by the render thread).
   `Err(mips)` → send the requests to the mip scheduler (T05), skip the tile.
4. `compositor.composite(&programs, &|h| store.try_get_hot(h))`:
   `Ready{slot}` → record in `ready`; `Deferred{missing}` → send `missing` to
   a loader job on the rayon pool that calls `store.get` (dedupe, and wake the
   render thread when done); `Empty` → record as empty (nothing to draw).
5. `ViewportRenderer::render(encoder, target, size, &plan, view.zoom,
   compositor.composite_view())` into the double-buffered viewport texture
   (`Rgba8Unorm`, **not** sRGB), submit, send `ViewportFrame(texture)`.
6. If `!plan.complete` or loads are pending, request another frame.

The render thread **never** calls `TileStore::get` itself.

**Acceptance** S2 on B1: ≥ 60 fps fit ↔ 3200 %, never a black/missing tile
(coarser fallback instead), full detail < 250 ms after stopping.

## M1-T08 — Open, close, tabs

**Files** `crates/fx-engine/src/{documents.rs,lib.rs}`, `crates/fx-app`,
`ui/js/*` (tabs, status bar), `Cargo.toml` (+ `rfd`).

**Spec**
* Action `dlg:open` (and `Ctrl+O`) in native mode → native file dialog
  (`rfd`, filters: TIFF, PNG, JPEG, All). The Fotox mock dialog stays for
  browser mode.
* Import runs as a job with `progress` messages; the document appears as
  soon as the import finishes (progressive display *during* import is a
  bonus, not required).
* `document_opened`, `active_document`, `view` messages; Fotox document tabs
  created from them (name, `@ zoom %`, `(RGB/16)`); tab click →
  `activate_document`; close button → `close_document`; `tab:close` action.
* Drag & drop of a file onto the window opens it (winit `DroppedFile`).
* Command line: `fotox.exe FILE…` opens files.

**Acceptance** Open B1, B2 and a small PNG in three tabs, switch between
them, close them; RAM returns near the empty-app baseline after closing
(tiles freed).

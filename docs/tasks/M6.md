# M6 — Transform and vector

> **Draft by Claude (25 Sep 2026), not approved yet.** Refine when M5 is
> accepted. Decisions in M6-T00 first — T00-1 and T00-2 change the plan.

Goal: change geometry — Free Transform (scale, rotate, skew, distort,
perspective, warp), Crop, Image Size, Canvas Size, rotate/flip, view rotation
— and add live vector content: shape layers and text layers that stay sharp
at every zoom, plus the basic layer styles (drop shadow, stroke, outer glow,
colour overlay, inner shadow).

Exit criteria (proposed — add to `PERFORMANCE.md` §4 when approved):

| Id | Scenario | Target |
| --- | --- | --- |
| S16 | Free Transform of a 10 000 × 10 000 layer of B3, drag a corner at fit | preview ≥ 30 fps; Enter → final result ≤ 20 s, UI responsive |
| S17 | B1: Image ▸ Rotate 90° | ≤ 30 s (a pixel permutation: I/O bound) |
| S18 | B1: Image Size to 50 %, Bicubic | ≤ 60 s |
| S19 | Text layer, 48 pt, typing at 100 % | keystroke → pixels ≤ 50 ms |
| S20 | 100 shape layers + 20 text layers on B1, pan/zoom | S2 still met |

Read first: `docs/ARCHITECTURE.md` §4.3 (offsets), §4.5, §4.7;
`crates/fx-render/src/viewport.rs` ("Rotation is not supported yet (M6)");
`crates/fx-engine/src/mips.rs` and `docs/tasks/HOWTO.md` R6 (vector tiles

## M6-T00 — Decisions (Rob)

Each answer becomes a `D-0xx` line in `DECISIONS.md`. The bold answer is
Claude's recommendation.

1. **Vector renderer.** The roadmap says "Vello", but Vello (GPU) pins its own
   `wgpu` version, and Fotox's `wgpu` is dictated by the vendored Graphite
   shell (29.0) — they will rarely match. Options: `vello_cpu` (same
   project, CPU, sparse strips, no wgpu), `tiny-skia` (CPU, mature, Skia's
   anti-aliasing), or Vello GPU only if the versions line up. Shapes and text
   render **into tiles on rayon** (R6) in every option, so the choice is
   contained in one module. **`vello_cpu` if its API is stable at the time,
   else `tiny-skia`.**
2. **Text stack**: `parley` (layout, bidi, line breaking) + `skrifa` (outlines)
   + `fontique` (system font enumeration on Windows) — the Linebender stack,
   pairs with `vello_cpu`; or `cosmic-text` (one crate, also mature). **Parley.**
3. **Resampling filters**: Nearest, Bilinear, Bicubic (Keys a = −0.5,
   "Bicubic"), Bicubic Smoother (Mitchell–Netravali B = 1/3, C = 1/3) for
   enlarging, Bicubic Sharper (Keys a = −0.75) for reducing, Lanczos-3 (Fotox
   extra), and "Bicubic Automatic" = Sharper when reducing, Smoother when
   enlarging. Reductions below 50 % first pick the mip level (exact box
   averages), then resample from it. **Yes.**
4. **Warp**: one bicubic Bézier patch (4 × 4 control points, Photoshop's
   default warp grid) + the preset styles later. Split/custom grids: later.
   **Yes.**
5. **Layer styles in M6**: Drop Shadow, Stroke, Outer Glow, Color Overlay,
   Inner Shadow. Bevel, Satin, Inner Glow, Gradient/Pattern Overlay: later.
   **Yes.**
6. **No smart objects**: transforms resample the pixels (Photoshop's
   behaviour on a normal layer); repeated transforms lose a little quality,
   as in Photoshop. Shape and text layers transform losslessly (their geometry
   is transformed). **Yes.**
7. **Crop "Delete Cropped Pixels" default off** (pixels outside the canvas
   are kept, like Photoshop's current default). **Yes.**

## M6-T01 — Resampling core (`fx-ops::resample`)

**Files** `crates/fx-ops/src/resample/{mod.rs,kernels.rs,mapping.rs,warp.rs}`.

* `pub enum Mapping { Affine([f64; 6]), Projective([f64; 9]), Warp(BezierPatch) }`
  from *source* layer pixels to *destination* document pixels, with inverses
  (`Warp`: see below).
* `pub fn resample(src: &TiledImage, src_offset: (i32, i32), store, mapping: &Mapping, filter: Filter, level_scale: f32, dst_tiles: &[(u32, u32)]) -> Vec<((u32, u32), TileBuffer)>`:
  for each destination tile, inverse-map its pixel centres, find the source
  bounding box (+ kernel support), fetch only those source tiles into a small
  per-task cache, sample **premultiplied** (then un-premultiply), outside the
  source = transparent. Destination tile set = tiles covering the mapped
  bounding box of the source's non-empty tiles.
* Minification: when the local scale (Jacobian) is < 0.5, sample from mip
  level ⌊log₂(1/scale)⌋ (compute missing mips first with `ensure_mip`), then
  the chosen kernel — no aliasing, bounded cost.
* **Warp**: forward-map the patch into a 64 × 64 grid of quads, split into
  triangles; per destination tile, a spatial list of the triangles touching
  it; per pixel, barycentric coordinates in its triangle → source position.
  Fold-overs: the last triangle drawn wins (Photoshop shows fold-overs too).
* Exact cases take shortcuts: an integer translation = `OffsetLayer` (no
  resampling), quarter-turn rotations and flips = pixel permutations (T02).

**Tests** identity mapping = exact copy; translate by (0.5, 0) bilinear =
the average of neighbours; rotate 30° then −30° (Bicubic) keeps a smooth
image within 2/255 away from edges; 25 % reduction of a 1-px checkerboard =
flat 50 % grey ± 1/255 (no moiré); half-transparent red on transparent: no
dark fringe; warp with the identity patch = exact copy (± rounding).

## M6-T02 — Image geometry: rotate, flip, canvas size, image size

**Files** `crates/fx-core/src/command.rs`, `crates/fx-ops/src/permute.rs (new)`,
`crates/fx-engine/src/ops.rs`, UI dialogs (`canvas-size`, `image-size`,
`rotate-arbitrary` exist as mocks).

* `Command::RotateCanvas { quarter_turns: i8 }`, `FlipCanvas { horizontal: bool }`
  (`img:rot90cw`, `img:rot90ccw`, `img:rot180`, `img:flip-h`, `img:flip-v`): every
  pixel layer, mask and the selection: tile (tx, ty) → its rotated position,
  pixels transposed inside the tile (exact, no resampling), offsets
  recomputed so layers stay where they were relative to the canvas; the
  document's width/height swap for odd turns. Tiles of other levels: dirty.
  Shape/text layers: their transform gets the rotation (lossless).
  Arbitrary angle (`dlg:rotate-arbitrary`): a `Transform` of every layer
  (T01) + canvas grown to the rotated bounding box.
* `Command::CanvasSize { width, height, anchor: Anchor9 }` (Alt+Ctrl+C):
  only offsets and the document size change — **no pixel is rewritten**
  (D-015). Pixels outside the new canvas are kept (they reappear if the
  canvas grows again).
* `Command::ImageSize { width, height, ppi, resample: Option<Filter> }`
  (Alt+Ctrl+I): `None` = change ppi only (print size); else every pixel
  layer and mask resampled (T01) as a job (R2) with progress, offsets and
  shape/text transforms scaled, layer styles' sizes scaled (Photoshop's
  "Scale Styles" on).

**Tests** four 90° turns = the original, tile handles equal where tiles were
uniform; flip H twice = original; canvas size then back = identical document
(same tile handles); image size 50 % then 200 % of a smooth image within a
Bicubic tolerance.

## M6-T03 — Crop tool

**Files** `crates/fx-engine/src/tools/crop.rs`, `crates/fx-core/src/command.rs`.

* Crop tool (C): on activation a box = the canvas; 8 handles + a
  rule-of-thirds grid (overlay, M5-T02); drag a handle resizes (Shift keeps
  the ratio, Alt from the centre), drag inside moves the image under the box
  (Photoshop moves the image, the box stays centred — **simplification: move
  the box**, say so in the report), drag outside rotates (straighten). Ratio
  / W×H / "Delete Cropped Pixels" from the option bar. Enter or the ✓ commits,
  Esc cancels. The area outside the box is shaded 50 % (overlay).
* `Command::Crop { rect: (i32, i32, u32, u32), angle_deg: f64, delete_cropped: bool }`:
  angle 0 and not deleting → canvas size + offsets (instant, like
  `CanvasSize`); deleting → tiles entirely outside dropped, partial edge
  tiles cleared outside the rect; angle ≠ 0 → rotate every layer (T01) about
  the box centre, then crop.
* `img:crop` (crop to the selection's bounding box) and `dlg:trim` (trim
  transparent or top-left-colour borders) reuse the command.

**Tests** crop without deleting then Canvas Size back = the original
document; crop with delete leaves no pixel outside; a 10° straighten of a
horizon image gives a level horizon (compare with rotating by T01 directly).

## M6-T04 — Free Transform and Warp

**Files** `crates/fx-engine/src/tools/transform.rs`, `crates/fx-engine/src/preview.rs`
(shared with M4-T05's filter preview), `crates/fx-core/src/command.rs`.

* Ctrl+T (and Edit ▸ Transform ▸ Scale / Rotate / Skew / Distort /
  Perspective / Warp / Flip H / Flip V / Rotate 90°…). Target: the active
  pixel layer (its content bounds: non-empty tiles, refined to the exact
  alpha bounds on the edge tiles); with a selection, the selected pixels are
  lifted into a floating layer first (cut + new layer, merged back on commit
  — one history step "Free Transform").
* Handles (overlay): 8 handles + the reference point; drag corner = scale
  (proportional by default, Shift = free — Photoshop 2019+), Alt = about the
  reference point, drag outside = rotate (Shift = 15° steps), Ctrl+corner =
  distort, Ctrl+Shift+side = skew, Ctrl+Alt+Shift+corner = perspective. Option
  bar: X, Y, W %, H %, angle, H/V skew, interpolation, warp toggle; Enter /
  ✓ commits, Esc cancels.
* **Warp** mode: the 4 × 4 control points of the patch and the grid as
  overlay; drag a point or the grid inside (moves the nearest points,
  weighted).
* **Preview**: the mapped layer is resampled at the **view level L** for the
  visible tiles only, into derived tiles of a preview copy of the layer
  (latest request wins, as in M4-T05); while a handle is being dragged, use
  level L + 1 (quarter of the work) and refine to L when the pointer stops
  for 150 ms. The original layer is hidden in the preview snapshot.
* Commit: `Command::Transform { layer, mapping, filter }` applied as a job
  (R2, progress) through `ctx.ops.resample` (R1a); shape/text layers get their
  transform changed instead (lossless, instant).

**Tests** a sequence of synthetic drags produces the expected mapping (scale
about the reference point, rotation snap, distort corner); Esc restores the
exact document; transforming a selection-floated area leaves a transparent
hole and the moved pixels (one undo step restores both).

## M6-T05 — View rotation

**Files** `crates/fx-render/src/{viewport.rs,frame.rs,gpu/viewport.rs,gpu/viewport.wgsl}`,
`crates/fx-engine/src/{view.rs,tools/rotate_view.rs}`.

* `ViewTransform` gains `rotation: f64` (radians, about the view centre).
  `visible_tiles` = the tiles covering the doc-space bounding box of the
  rotated screen rectangle, then filtered by exact polygon/tile intersection —
  **still bounded by the screen size** (extend the existing test with angles
  0°, 30°, 45°, 90°).
* The viewport pass draws each tile quad with the rotation; sampling stays
  nearest ≥ 100 % and linear below (rotated nearest looks jagged at 100 %:
  use linear when rotation ≠ 0).
* Pointer → document mapping includes the rotation (every tool gets correct
  coordinates for free through `DocPointer`).
* Rotate View tool (R): drag rotates (Shift = 15° steps), Esc or "Reset View"
  = 0°. The `View` message already carries `rotation_deg`. The rulers stay
  screen-aligned and keep showing document coordinates along the unrotated
  axes (good enough; revisit if it confuses).

**Tests** screen ↔ document round trips with rotation; plan of a rotated
view covers exactly the needed tiles (no black corners: a GPU test at 45°).

## M6-T06 — Shape layers

**Files** `crates/fx-core/src/{layer.rs,vector.rs (new)}`,
`crates/fx-render/src/{program.rs,vector.rs (new)}` (the renderer of T00-1),
`crates/fx-engine/src/{tools/shape.rs,tools/path_select.rs}`,
`crates/fx-io/src/fxd/manifest.rs` (new layer kind, `serde(default)` fields).

* `LayerKind::Shape { shape: VectorShape, fill: Option<Paint>, stroke: Option<StrokeStyle>, transform: [f64; 6], cache: TiledImage }`
  with `VectorShape::{Rect { w, h, radii: [f64; 4] }, Ellipse { w, h }, Polygon { sides, star_inset }, Line { length, width }, Path(Vec<PathEl>)}`,
  `Paint::Solid([u16; 4])` (gradients later), `StrokeStyle { width, align: Inside | Center | Outside, paint, dash: Option<Vec<f64>> }`.
* **Rendering = derived tiles** (R6): `cache` is a `TiledImage` (document
  depth) whose tiles are rendered on demand **at the requested level** from
  the geometry (never from mips: every zoom is sharp), `VectorRequest { layer,
  level, tx, ty }` next to `MipRequest`, rendered on rayon, `set_derived_slot`.
  The program key includes a hash of (shape, paints, transform) so edits
  refresh by themselves. Anti-aliasing: the renderer's analytic coverage.
* Level 0 rendering is the same function: export, merge and rasterise
  (`raster:shape`, `raster:layer`) call it for every level-0 tile.
* Shape tools (U): drag = bounding box (Shift = square, Alt = from centre),
  option bar fill/stroke colour, stroke width, radius, sides; a new shape
  layer per shape (`Command::AddLayer { layer: NewLayer::Shape {…} }`),
  editing = `Command::SetShape { layer, … }` (merged while dragging a value,
  like opacity).
* Path Selection (A): select/move shape layers (drag = transform change,
  no pixels); Direct Selection / Pen: **out of scope** for M6 (the `Path`
  variant exists for PSD import and later tools).

**Tests** a rect shape at level 0 = the exact coverage of an axis-aligned
rect; the same shape at level 2 equals the level-0 render downsampled within
2/255 at edges (both are "correct", the higher level is sharper); editing the
fill changes the program key; rasterise → a pixel layer with the level-0
render.

## M6-T07 — Text layers

**Files** `crates/fx-core/src/{layer.rs,text.rs (new)}`,
`crates/fx-render/src/text.rs (new)`, `crates/fx-engine/src/{tools/type.rs,fonts.rs (new)}`,
`crates/fx-protocol/src/lib.rs`, `ui/js/native/type.js (new)`.

* `LayerKind::Text { text: String, runs: Vec<TextRun>, frame: TextFrame, align, antialias, transform, cache: TiledImage }`
  with `TextRun { range, family, style, size_pt, color, tracking, leading }`,
  `TextFrame::Point | Box { w, h }` (paragraph text wraps). Size in px =
  `size_pt × ppi / 72` (Photoshop).
* Layout with the T00-2 stack, glyph outlines → the vector renderer (T06), so
  text is sharp at every level and anti-aliasing matches shapes ("Sharp",
  "Crisp", "Strong", "Smooth" map to renderer settings / hinting — VERIFY).
* Fonts: `fonts.rs` enumerates system fonts once (background, at start) and
  sends `EngineToUi::Fonts { families: Vec<FontFamily { name, styles }> }`; the
  type option bar uses it instead of its fixed list.
* **Editing** (the UI owns keyboard and IME): clicking with the Type tool (T)
  creates or enters a text layer; the UI places an invisible `<textarea>`
  (focused, so CEF's IME works) and sends
  `UiToEngine::TextEdit { doc, layer, text, selection: (start, end) }` on every
  input; the engine lays out, renders the visible tiles of the text's area,
  and draws caret + selection highlight as overlay (it knows the glyph
  positions). Direct input stays disabled while the textarea has focus
  (`DirectInput { enabled: false }` — already the rule for text fields).
  Commit: Ctrl+Enter, Enter on the numeric keypad, the ✓, a click outside or
  another tool → one history step "Type Tool". Esc = cancel the edit.
* `raster:type` rasterises; `type:to-shape` / `type:work-path`: later.

**Tests** layout of a known string with a bundled test font (add a small OFL
font under `crates/fx-render/tests/data/`) gives stable glyph positions;
point text at 72 ppi 12 pt = 12 px em; a text edit of one character
re-renders only the tiles its line touches.

## M6-T08 — Layer styles (basic)

**Files** `crates/fx-core/src/{layer.rs,styles.rs (new)}`,
`crates/fx-render/src/{program.rs,styles.rs (new),gpu/composite.wgsl}`,
UI dialogs (`blending-options`, `style-drop-shadow`, `style-stroke`,
`style-outer-glow`, `style-color-overlay`, `style-inner-shadow` exist as mocks).

* `Layer::styles: Option<LayerStyles>` with `DropShadow { blend, color, opacity, angle, use_global_light, distance, spread, size }`,
  `Stroke { size, position: Outside | Inside | Center, blend, opacity, color }`,
  `OuterGlow { blend, opacity, color, spread, size }`, `ColorOverlay { blend, color, opacity }`,
  `InnerShadow { blend, color, opacity, angle, distance, choke, size }`;
  `Document::global_light_angle`. Serde (the `.fxd` manifest gets them with
  `serde(default)`).
* **Effect images are derived tiles** (R6): computed per layer and level from
  the layer's alpha at that level (distances × 2⁻ᴸ): drop shadow = Gaussian
  (M4) of the alpha dilated by `spread`, shifted by (distance, angle); outer
  glow = blurred dilated alpha; stroke = dilation/erosion ring of the alpha
  (anti-aliased, distance transform of M5-T03); inner shadow = blurred shifted
  inverse alpha ∩ alpha; colour overlay = no image (a solid colour clipped to
  the content). Aprons can span several tiles (size up to 250 px at level 0):
  computed only for requested tiles.
* **Program**: the layer becomes, in Photoshop's order — drop shadow, outer
  glow (each composited onto the backdrop with its own blend mode, alpha ×
  layer opacity), content (alpha = opacity × fill), then the interior effects
  (inner shadow, colour overlay) and stroke, each clipped to the content
  (source-atop) with its own blend mode. **Fill** affects the content only,
  **opacity** everything (this is why `fill` exists since M2). "Blend Interior
  Effects as Group" and the other advanced blending options: later. Order and
  blend details: VERIFY against Photoshop in M7.
* Layers panel: an "fx" marker on the row and the effects listed under it
  (toggle eye per effect); `LayerInfo.styles` carries the parameters for the
  dialogs; `layer:copy-style` / `layer:paste-style` / `layer:clear-style`.

**Tests** drop shadow of an opaque square: offset, blurred, correct colour
under a Normal backdrop; opacity 0 of the layer hides content and effects,
fill 0 hides only the content (the shadow stays — Photoshop's knockout
trick); stroke outside of a disc = a ring of the right width (± 0.5 px);
GPU = CPU for the new ops.

# M4 — Colour + first filters

> **Approved by Rob (25 Sep 2026).** The T00 decisions are recorded as
> `D-023`…`D-031` in `docs/DECISIONS.md`; the proposals of the cards below are
> binding from here on.

Goal: what you see is right (colour-managed display), print is predictable
(soft proof, gamut warning, CMYK TIFF export), more adjustment layers, and
the filter framework with its first two filters — Gaussian Blur and Unsharp
Mask — with a live preview that never makes the UI wait.

Exit criteria (in `PERFORMANCE.md` §4 as of 25 Sep 2026: S10–S12 binding,
C1/C2 in the correctness table):

| Id | Scenario | Target |
| --- | --- | --- |
| S10 | B1: Gaussian Blur dialog open, drag Radius 1 → 50 px at fit and at 100 % | preview updates ≥ 10 times/s; the view is never blank or frozen |
| S11 | B1: Gaussian Blur 10 px, OK | final level-0 result ≤ 60 s, UI responsive throughout (pan/zoom ≥ 60 fps) |
| S12 | B1 with a display profile ≠ sRGB | S2 still met (the display LUT costs < 0.5 ms/frame) |
| C1 | sRGB document on an sRGB monitor | display = document values exactly (identity shortcut) |
| C2 | CMYK TIFF export of a test chart, FOGRA39 / RSWOP, relative colorimetric + BPC | every patch within ΔE00 ≤ 1 of Photoshop's conversion of the same file (Rob) |

## M4-T00 — Decisions (Rob)

**Answered 25 Sep 2026**: every recommendation in bold below is accepted and
recorded in `docs/DECISIONS.md` (`D-023` monitor profile, `D-024` CMYK
profiles, `D-025` intents, `D-026` CPU filters, `D-027` radius = σ, `D-028`
edges, `D-029` new adjustments, `D-030` merge/flatten, `D-031` `lcms2` +
`half`).

Each answer becomes a `D-0xx` line in `DECISIONS.md`. The bold answer is
Claude's recommendation.

1. **Monitor profile**: read the Windows default display profile with
   `WcsGetDefaultColorProfile` / `GetICMProfileW` (the `windows` crate is
   already a dependency of `fx-app`; add the `Win32_UI_ColorSystem` and
   `Win32_Graphics_Gdi` features), refreshed when the window moves to another
   monitor; plus a manual override in Preferences. **Yes.**
2. **CMYK profiles**: Fotox ships none. The Proof Setup / export dialogs list
   the CMYK profiles found in `C:\Windows\System32\spool\drivers\color`
   (Windows ships `RSWOP.icm`) and any `.icc` the user adds (copied to
   `%APPDATA%/Fotox/profiles`). Rob installs FOGRA39/51 (ECI, free download)
   himself. **Yes** — no licence question for us.
3. **Rendering intents**: perceptual, relative colorimetric (default, with
   black point compensation on), saturation, absolute colorimetric — exactly
   lcms2's. **Yes.**
4. **Filters run on the CPU** (rayon, f32) in M4, GPU compute later if S11 is
   missed. The CPU code is the reference either way. **Yes.**
5. **Gaussian Blur "Radius"** = the standard deviation σ in pixels, as far as
   we know Photoshop's (VERIFY in M7). **Yes.**
6. **Edges**: outside the *canvas* a filter sees the nearest canvas pixel
   (edge replicate); inside the canvas, where a layer has no pixels, it sees
   transparency. (Photoshop-like, VERIFY.) **Yes.**
7. **New adjustment layers in M4**: Vibrance, Color Balance, Black & White,
   Photo Filter, Channel Mixer, Posterize, Threshold, Gradient Map, and the
   six colour ranges of Hue/Saturation. Selective Color and Color Lookup wait.
   **Yes.**
8. **Merge / Flatten** rasterise with the GPU readback of M3-T07 when an
   adapter exists, else the CPU reference. Flatten fills transparency with
   white (Photoshop). **Yes.**

## M4-T01 — `fx-color`: profiles and transforms

**Files** `crates/fx-color/src/{lib.rs,profile.rs,transform.rs,lut.rs}`,
`crates/fx-color/Cargo.toml` (+ `lcms2`, `half`, `fx-core`).

* `pub fn profile(p: &fx_core::ColorProfile) -> Result<Profile, ColorError>`:
  `Srgb` → lcms2's built-in sRGB; `AdobeRgb1998` (primaries R 0.64/0.33,
  G 0.21/0.71, B 0.15/0.06, D65, gamma 563/256), `DisplayP3` (P3 primaries
  R 0.680/0.320, G 0.265/0.690, B 0.150/0.060, D65, sRGB curve), `ProPhotoRgb`
  (ROMM primaries R 0.7347/0.2653, G 0.1596/0.8404, B 0.0366/0.0001, D50,
  gamma 1.8 with the ROMM linear segment below 1/512) built with
  `Profile::new_rgb`; `Icc(bytes)` → `Profile::new_icc`. Cache by content hash.
* `pub fn display_lut(src, dst, intent, bpc) -> Lut3d` — **33³ grid**, RGBA
  f16 (`half`), A = 1.0 (or the gamut flag, T04), sampled on the encoded
  values of `src` at `i/32`; the GPU interpolates trilinearly.
* `pub fn pixel_transform(src, dst, intent, bpc, format) -> PixelTransform` —
  lcms2 transform for tile data (`TYPE_RGBA_8`, `TYPE_RGBA_16` with alpha copied
  — `cmsFLAGS_COPY_ALPHA`), `Send + Sync` (lcms2 transforms are thread-safe
  for `do_transform` — create one per job, share it across rayon workers;
  confirm in the crate docs and say so in the report).
* `pub fn same_profile(a, b) -> bool` — equal enum values, or equal ICC bytes
  (or equal MD5 profile ID header field when present).

**Tests** sRGB → sRGB LUT is the identity within 1/1023 at every grid node;
Adobe RGB (1, 0, 0) → sRGB is out of gamut and clips to (1, 0, 0) with
relative colorimetric; a round trip sRGB → ProPhoto → sRGB 16-bit changes no
channel by more than 2/65535 for in-gamut colours; profiles built from
primaries match the ICC files of the same spaces (if present on the machine,
else skip) within ΔE00 0.5.

## M4-T02 — Display transform in the viewport

**Files** `crates/fx-render/src/gpu/{viewport.rs,viewport.wgsl}`,
`crates/fx-engine/src/render.rs`, `crates/fx-app/src/{app.rs,render.rs}` (monitor
profile), `crates/fx-engine/src/lib.rs` (`EngineInput::DisplayProfile`).

* The viewport pass samples composite tiles (premultiplied f16). New step in
  `viewport.wgsl`, per fragment: un-premultiply → **3D LUT** (a 33³
  `Rgba16Float` 3D texture, linear filtering, coordinates
  `c · 32/33 + 0.5/33`) → premultiply → blend over the checkerboard as today.
  The checkerboard and the background are UI colours: **not** transformed.
* A uniform flag skips the LUT when `same_profile(document, monitor)` — then
  the output is bit-identical to today's (test C1).
* The LUT is per document (its profile) and per monitor: the render thread
  keeps `(doc profile hash, monitor profile hash, proof state) → LUT texture`
  and rebuilds only when one changes. Building (lcms2, 36 k samples) runs on
  the engine thread or a worker, never on the render thread; until it is ready
  the old LUT (or none) is used.
* The shell sends `EngineInput::DisplayProfile(Option<Vec<u8>>)` at start and
  when the window's monitor changes (`winit` `Moved` / `ScaleFactorChanged`,
  compare `current_monitor()`); `None` = assume sRGB.
* Status bar: the document profile name (already in `DocumentInfo.profile_name`).

**Tests** GPU test: an sRGB document with the identity flag → exact bytes;
with an Adobe RGB document on an sRGB "monitor", a mid-grey stays grey and a
saturated green matches the CPU lcms2 result within 2/255.

## M4-T03 — Profiles on import/export; Assign / Convert to Profile

**Files** `crates/fx-core/src/command.rs`, `crates/fx-ops/src/convert.rs`,
`crates/fx-io/src/{export.rs,tiff_write.rs}`, `crates/fx-engine/src/{engine.rs,export.rs}`,
`ui/js/data/{menus.js,dialogs.js}`.

* Import already reads embedded ICC (TIFF tag 34675, PNG iCCP, JPEG APP2 →
  `ColorProfile::Icc`). On open, if the profile differs from the working space
  (Preferences, default sRGB), the UI asks like Photoshop's *Embedded Profile
  Mismatch*: **Use the embedded profile** (default) / **Convert to working
  space** / **Discard** (assign working space). Engine message
  `EngineToUi::ProfileMismatch { doc, embedded, working }`, answered with a
  command.
* `Command::AssignProfile { profile }` — metadata only (the numbers stay, the
  look changes). `Command::ConvertProfile { profile, intent, bpc }` — pixel
  operation tile by tile on rayon with `pixel_transform` (level 0 of every
  pixel layer; mips become dirty); solid fill colours converted; masks and
  adjustment parameters untouched (Photoshop does the same). Both undoable.
* Menus: *Edit ▸ Assign Profile…*, *Edit ▸ Convert to Profile…*,
  *Edit ▸ Color Settings…* (working space, intent, BPC, mismatch policy) — add
  the items and dialogs to `menus.js` / `dialogs.js`; `node ui/tools/check-data.mjs`.
* Export embeds the document profile: TIFF tag 34675 (`tiff_write` gets
  `set_icc(bytes)`), PNG `iCCP` (the `png` encoder's ICC support), JPEG APP2
  (M3-T07's encoder). sRGB documents: embed sRGB too (Photoshop's default
  "Embed Color Profile" on).

**Tests** Assign changes no pixel; Convert sRGB → Adobe RGB → sRGB round trip
within 2/65535 (16-bit) for in-gamut pixels; an exported TIFF reopened has the
same profile bytes.

## M4-T04 — Soft proof, gamut warning, CMYK TIFF export

**Files** `crates/fx-color/src/{proof.rs,lut.rs}`, `crates/fx-render/src/gpu/viewport.wgsl`,
`crates/fx-io/src/{export.rs,tiff_write.rs}`, `crates/fx-engine/src/export.rs`, UI.

* **Proof Setup** (`View ▸ Proof Setup ▸ Custom…`): CMYK profile (T00-2 list),
  intent, BPC, "Simulate Paper Color". Per document, stored in `OpenDoc`
  (and in the `.fxd` manifest as optional metadata).
* **Proof Colors** (Ctrl+Y): the display LUT becomes
  document → CMYK → monitor: lcms2's proofing transform
  (`Transform::new_proofing`, flag `SOFT_PROOFING`), with the proof intent =
  the chosen intent, and the *proofing* intent (CMYK → monitor) = absolute
  colorimetric when "Simulate Paper Color" is on, relative colorimetric
  otherwise.
* **Gamut Warning** (Shift+Ctrl+Y): the LUT's alpha channel holds 1.0 for
  in-gamut nodes and 0.0 for out-of-gamut ones (lcms2 gamut check,
  `cmsFLAGS_GAMUTCHECK`); the shader paints `mix(gamut_colour, colour, a)` —
  grey 50 % by default. Trilinear filtering of the flag gives soft edges; use
  `a < 0.5` as the test.
* **CMYK TIFF export**: `ExportOptions.cmyk: Option<CmykTarget { profile, intent, bpc }>`;
  per band: flatten onto white (no alpha in CMYK export), RGB → CMYK with a
  `pixel_transform` (8 or 16 bit), `tiff_write` with `samples = 4`,
  Photometric 5 (separated), InkSet 1, the CMYK profile embedded. In TIFF CMYK,
  0 = no ink (lcms2's CMYK encoding matches; say so in a test).
* Export As dialog (M3-T07) gets "Convert to CMYK: [profile]".

**Tests** proof LUT of an sRGB document with RSWOP: pure sRGB blue is out of
gamut, mid grey is in gamut; CMYK export of a 5-patch image → reopen the raw
TIFF values and compare with lcms2 directly (same numbers); Photoshop opens
the file with the embedded profile (Rob, C2).

## M4-T05 — Filter framework (`fx-ops::filter`)

**Files** `crates/fx-ops/src/{lib.rs,filter.rs,neighbourhood.rs}`,
`crates/fx-core/src/command.rs`, `crates/fx-engine/src/{engine.rs,filters.rs,render.rs}`,
`crates/fx-protocol/src/lib.rs`, `ui/js/native/filters.js` (new).

* `fx_core::FilterParams` (serde, `#[serde(tag = "kind")]`): one variant per
  filter (`gaussian_blur { radius }`, `unsharp_mask { amount, radius, threshold }`, …).
* `Command::ApplyFilter { layer: LayerRef, filter: FilterParams }` (R1), applied
  through `ctx.ops.filter(…)` (R1a — this card adds `PixelOps` and
  `fx-engine/src/ops.rs`). Target:
  the layer's pixels (the mask when the mask is the edit target — M5);
  locked pixels → `Locked`; adjustment/group layers → `NotAllowed("the layer
  has no pixels; rasterise it first")`. With a pixel selection (M5) the result
  is `lerp(original, filtered, selection)`.
* `fx_ops::filter::apply_tiles(image: &TiledImage, store, params, level, tiles: &[(u32, u32)], canvas: Rect) -> Vec<((u32, u32), TileBuffer)>`:
  gathers each tile's `Neighbourhood` (tile + apron from neighbours; empty
  neighbours are transparent without a fetch; beyond the canvas edge-replicate,
  T00-6), converts to f32 **premultiplied**, calls the filter's `run`,
  converts back with rounding. Output tile set = non-empty tiles grown by
  `ceil(apron / 256)` tiles in each direction, clipped to the canvas.
* **Live preview** (R4): `UiToEngine::FilterPreview { doc, layer, filter }`,
  `FilterPreviewCancel { doc }`; the engine keeps one `FilterPreview` per
  document with the latest parameters (a new request replaces an unfinished
  one — computation already running finishes, its result is dropped if
  stale). Preview = the **visible tiles at the current view level L**,
  computed with distances scaled by 2⁻ᴸ, stored as derived tiles in a clone of
  the layer's `TiledImage` (`set_derived_slot` at level L; level 0 untouched
  unless L = 0). The render snapshot uses that clone for the layer. Panning
  or zooming extends/recomputes the preview for the new visible tiles
  (priority: centre out, like `plan_frame`).
* **OK**: the dialog closes at once; a job (R2) computes level 0 of every
  output tile (progress "Gaussian Blur…"); meanwhile the preview stays on
  screen and the layer is busy (R2 §5). The result is committed with
  `History::record` (R1b); mips of changed tiles become dirty.
  **Spec test**: `Command::apply` on the before-document gives the same
  pixels as the job.
* **Cancel**: drop the preview, redraw from the untouched layer.
* `filter:last` (Ctrl+F): re-apply the last filter with its parameters;
  Alt+Ctrl+F: open its dialog with them.

**Tests** a 3×3-tile image with content across the seams: tiled result =
naive whole-image reference; an empty layer produces no tiles; a single
opaque pixel in the middle of a tile spreads into the neighbour tiles only
when the apron reaches them; cancelling a preview leaves the snapshot equal to
the document.

## M4-T06 — Gaussian Blur and Unsharp Mask

**Files** `crates/fx-ops/src/{gaussian.rs,unsharp.rs}`, `ui/js/data/dialogs.js`
(the `gaussian-blur` / `unsharp-mask` dialogs get `rng()` fields: Radius
0.1–1000 px in tenths, Amount 1–500 %, Threshold 0–255).

* **Gaussian**: σ = radius × level_scale (T00-5). Kernel half-width
  `ceil(3σ)`. σ ≤ 32: exact separable convolution (normalised f32 kernel),
  horizontal pass over the apron rows, then vertical. σ > 32: three
  successive box blurs with widths from Kovesi's formula ("fast almost-Gaussian
  filtering"), each a running sum — O(1) per pixel whatever σ. Premultiplied.
  Apron = `ceil(3σ)` px (box path: the sum of the three half-widths).
  Radius beyond the preview level's image size: clamp the apron to the image.
* **Unsharp Mask**: `blur = gaussian(σ = radius)`, per channel of the straight
  colour `d = orig − blur`; if `|d| · 255 < threshold` keep `orig`, else
  `orig + amount · d`, clamped. Alpha unchanged. (Photoshop applies it per
  channel; VERIFY in M7.)
* Both scale-consistent enough to preview at level L with σ·2⁻ᴸ; below σ·2⁻ᴸ
  < 0.3 the preview is the unfiltered level (a note in the dialog is not
  needed — at 100 % the preview is exact).

**Tests** σ ≤ 32 path vs a double-precision reference on random 16-bit data:
max error ≤ 1/65535·4; box path vs exact Gaussian: RMS error ≤ 1 % of range
for σ = 40, 100; blurring a constant opaque image is exact (no darkening at
tile seams or canvas edges); a transparent layer with one opaque square keeps
no dark fringe (premultiplied); USM with amount 0 or threshold 255 is the
identity. Benchmark `fotox-cli bench blur --file B1.tif --radius 10` (S11).

## M4-T07 — More adjustment layers

Recipe R7 for each. Kinds: **LUT** (per channel, value only) / **Matrix**
(new `AdjustKind::Matrix { m: [f32; 12] }`: 3×3 + offset) / **Luma LUT** (new
`AdjustKind::LumaLut(Arc<Lut>)`: RGB out as a function of luminance) / **Per-pixel**
(new kinds in the shader). Formulas marked VERIFY carry their source.

| Adjustment | Parameters (Photoshop's) | Kind | Formula (reference) |
| --- | --- | --- | --- |
| Posterize | levels 2–255 | LUT | `round(x·(n−1))/(n−1)` |
| Threshold | level 1–255 | Luma LUT | `luma ≥ level/255 ? 1 : 0`, luma = 0.299R + 0.587G + 0.114B (VERIFY) |
| Gradient Map | stops `[(pos, rgb)]`, reverse, dither off | Luma LUT | gradient evaluated at luma (linear interpolation between stops, encoded values) |
| Channel Mixer | 3×3 in %, constants, monochrome | Matrix | `out_c = Σ m_ck·in_k + const_c`; monochrome = one row for all |
| Photo Filter | colour, density 0–100 %, preserve luminosity | Per-pixel | `mix(c, c·filter (multiply), density)`, then restore luma if preserve (VERIFY) |
| Black & White | reds, yellows, greens, cyans, blues, magentas (−200…300 %), tint (hue, sat) | Per-pixel | sort (max, mid, min); gray = min + (mid−min)·w(secondary) + (max−mid)·w(primary) (the commonly used reconstruction; VERIFY) |
| Color Balance | shadows/midtones/highlights × 3 sliders (−100…100), preserve luminosity | LUT (+ luma restore per-pixel if preserve) | GIMP's colour-balance transfer curves (documented reconstruction; VERIFY) |
| Vibrance | vibrance, saturation (−100…100) | Per-pixel | saturation boost weighted by `1 − current saturation`, skin-tone protection omitted (VERIFY) |
| Hue/Saturation ranges | master + 6 ranges (reds…magentas) each with hue/sat/light and 4 range sliders | Per-pixel | per-pixel weight of each range from the hue distance (trapezoid of the 4 sliders), parameters blended by weight |

`Adjustment` gains the variants; existing documents stay readable (new
variants only). Dialogs exist as mocks for most (`dlg:vibrance`,
`dlg:color-balance`, `dlg:black-white`, `dlg:photo-filter`,
`dlg:channel-mixer`, `dlg:posterize`, `dlg:threshold`, `dlg:gradient-map`):
convert their value fields to `rng()` and map them in
`ADJUSTMENT_DIALOGS`.

**Tests** per adjustment: identity parameters = unchanged pixels (except
Threshold/Posterize/Gradient Map, which have no identity: test hand values);
GPU = CPU within 1e-3; B3's builder may add one of each (update its layer
count test).

## M4-T08 — Merge and flatten

**Files** `crates/fx-core/src/command.rs` (`MergeLayers`, `Flatten` exist as
M4 variants; add `StampVisible`), `crates/fx-engine/src/{ops.rs,export.rs}`
(share the band compositor); the Layer menu ids `layer:merge`,
`layer:merge-visible`, `layer:flatten`, `layer:flatten-visible` already exist.

* Rasterising needs the compositor (`fx-render`), reached through
  `ctx.ops.composite(…)` (R1a): the selected layers as an isolated group, each
  with its own mode, opacity, mask and clipping, adjustments baked in, per tile
  at level 0, into a new pixel layer. Big documents: the engine runs the
  command as a job (R2) with progress; the command itself is ordinary.
* Merge Down (Ctrl+E) = merge the active layer into the one below; result
  named after the lower layer, Normal, 100 %. Merge Visible (Shift+Ctrl+E):
  every visible layer. Flatten: every visible layer composited onto white,
  hidden layers discarded (the UI asks "Discard hidden layers?" like
  Photoshop). Stamp Visible (Alt+Shift+Ctrl+E): a new layer on top with the
  composite, nothing removed.
* Only tiles where any merged layer has content are computed; empty stays
  empty (except Flatten's white).

**Tests** merging two Normal layers equals the composite of both; merging a
Multiply layer onto a Normal one equals what the two looked like (composite
over transparency, then over the same backdrop); undo restores both layers
with their tile handles (no pixel copy).

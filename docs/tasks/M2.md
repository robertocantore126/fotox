# M2 — Layers and blend modes

Goal: a real layer stack — pixel layers, groups, masks, clipping, all blend
modes, six adjustment layers — composited lazily and fast, with live Layers
and History panels and undo.

Exit criteria: S4, S5, S6, S8 (`docs/PERFORMANCE.md`) on B3, recorded.

Read first: `docs/BLEND_MODES.md` (the spec), `docs/ARCHITECTURE.md` §4–5,
`crates/fx-core/src/command.rs`. These cards are less detailed than M0/M1
on purpose; they will be refined after M1 review.

---

## M2-T01 — Layer commands

Implement every command marked `M2` in `fx-core::command::Command`, with
validation first and mutation after (all or nothing). Rules:

* `AddLayer`: above the active layer, inside its group if the active layer
  is in a group; becomes the only selected layer. Default names like
  Photoshop: "Layer 1", "Group 1", "Curves 1"… (counter per kind, per document).
* `DeleteLayers`: deleting a group deletes its children; selection moves to
  the layer below (or above if none).
* `DuplicateLayers`: " copy" suffix; tile handles are shared (no pixel copy).
* `MoveLayer`: reject moving a group into itself or its descendants.
* `OffsetLayer`: pixel layers only (+ mask if linked); rejects `locked_position`.
* `AddMask RevealAll/HideAll` = `Empty`/`Solid` mask tiles (no memory).
* `DeleteMask {apply: true}`: multiply alpha by the mask — a pixel operation
  over the mask's non-uniform tiles only, on rayon.
* Every command: an effect (`CommandEffect`) listing exactly what changed.

Tests: one per command (success + each error), plus undo/redo round trips
through `History`. Plus `fx-engine`: `Document` → `Vec<LayerInfo>` conversion
(top → bottom, depth).

## M2-T02 — Blend modes: CPU reference + GPU

`fx-render::reference`: straight f64 implementation of `BLEND_MODES.md` §2–5.
`blend.wgsl`: one function `blend(mode_id, cb, ab, cs, as) -> vec4`
(premultiplied out) matching it. Test harness as in `BLEND_MODES.md` §7.
`BlendMode::shader_id` numbering is the contract between Rust and WGSL.

## M2-T03 — Stack compositor

Extend the compositor to the full stack for one output tile: visibility,
opacity/fill, masks (`outside_value` beyond mask bounds), layer offsets
(up to 4 source tiles, `ARCHITECTURE.md` §4.3), isolated vs pass-through
groups, clipping groups, solid fills. One compute dispatch per output tile
with a small per-tile "layer program" (array of ops) in a storage buffer —
not one dispatch per layer. Composite key + cache as in `compositor.rs` docs.
Test: CPU reference compositor (f64) vs GPU on generated stacks (random
modes/opacities/masks/groups, 30 layers), max error ≤ 1/1024.

## M2-T04 — Adjustment layers

`BrightnessContrast`, `Levels`, `Curves`, `Exposure`, `HueSaturation`
(master), `Invert`. Evaluated in the compositor shader; Levels/Curves baked
into 1D LUTs (4096 entries × 4 channels, f16). Curves interpolation:
monotone cubic like Photoshop's (**VERIFY** in M7). CPU reference + tests.
UI: the existing Fotox adjustment dialogs send `SetAdjustment` on every
change (live) when editing an adjustment *layer*.

## M2-T05 — Stack split cache

As documented in `compositor.rs`. Activate when a layer receives ≥ 2 edits
within 1 s (slider drags), release after 2 s idle. Measure S5 with and
without; report both.

## M2-T06 — Layers and History panels, live

Fotox Layers panel driven by `layers` messages: thumbnails placeholder,
eye, name (double-click rename), blend drop-down, opacity/fill fields and
scrubby sliders, lock toggles, mask indicator, group expand/collapse,
multi-select (Ctrl/Shift), drag to reorder/into groups, footer buttons
(new layer, group, mask, adjustment menu, delete). Every change →
`command`. History panel from `history`; Ctrl+Z / Ctrl+Shift+Z / Ctrl+Alt+Z
like Photoshop. Must stay fluid with 1 000 layers (virtualised list).

## M2-T07 — Layer thumbnails

Engine renders each requested layer alone at the deepest mip level that
gives ≥ `size` px, scales to fit, sends a binary `thumbnail`. Throttle:
re-render a layer's thumbnail at most once per 500 ms while it changes.

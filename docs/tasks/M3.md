## M3-T00 — Decisions (Rob)

Each answer becomes a `D-0xx` line in `DECISIONS.md`. Claude's recommendation
is in **bold**.

1. **Checksum** of chunks: `crc32c` crate (CRC-32C, hardware-accelerated) or
   `crc32fast` (plain CRC-32). New dependency either way. **`crc32fast`** —
   widely used, same safety for this purpose.
2. **Tile codec** in `.fxd`: zstd level 3 (spec; `zstd` is in the workspace,
   it builds C code — fine, CEF already needs a C toolchain) vs `lz4_flex`
   (pure Rust, ~3× faster to compress, files ~20–30 % bigger). S7 favours LZ4
   (only changed tiles are compressed, so both likely meet it); size favours
   zstd. **zstd level 1** for Save (fast), **level 3** for Save As / compaction.
   The codec byte in each tile keeps both readable forever.
3. **Manifest encoding**: zstd-compressed JSON (spec). **Yes** — debuggable
   with `fotox-cli fxd dump`, and small (B3: ~220 layers × a few hundred
   non-empty slots).
4. **Preview chunks**: store the flattened composite at levels ≥ 3 on every
   save (**yes** — it makes S3 independent of the layer count; ~1.5 % of the
   level-0 size), *and* per-layer mips ≥ 3 as derived tiles (**yes** — the
   first frame at fit needs them when a layer is edited right after opening).
5. **The file stays open while its document is open** (tiles are read from it
   lazily), opened read+write by Fotox only; Save appends to it. Save As to
   another path copies every tile (no cross-file references). **Yes.**
6. **Is the pixel selection saved?** Photoshop does not save the active
   selection. **No** (it is not in the manifest).
7. **JPEG export encoder**: `jpeg-encoder` (pure Rust, baseline + progressive,
   4:2:0 / 4:4:4). **Yes.**
8. **Compressed TIFF export** (Deflate) needs a deflate crate (`flate2` with
   the pure-Rust `miniz_oxide` backend). Worth it? Uncompressed 16-bit TIFFs
   of B1 are 5.4 GB; Deflate saves ~10–30 % on photos and costs time.
   **Not now** (M8 batch export can revisit).

## M3-T01 — `.fxd` container (`fx-io::fxd`)

**Files** `crates/fx-io/src/fxd/{mod.rs,container.rs,tests.rs}`, root
`Cargo.toml` (+ the checksum crate, T00-1).

**Layout** (all integers little-endian; this is the normative version of
`FILE_FORMAT.md` — update that file in the same commit):

```text
Header, 64 bytes, at offset 0
  0  [u8; 8]  magic "FOTOXFXD"
  8  u32      format version = 1
 12  u32      flags = 0 (reserved)
 16  [u8;16]  writer, e.g. "fotox 0.1.0", zero-padded (informational)
 32  [u8;32]  reserved, zero

Chunk = 16-byte chunk header + payload
  0  u8   kind: 1 TILE, 2 MANIFEST, 3 PREVIEW_TILE
  1  u8   flags = 0
  2  u16  reserved = 0
  4  u64  payload length in bytes
 12  u32  checksum of the payload (T00-1)

TILE / PREVIEW_TILE payload
  0  u8   PixelFormat (0 Rgba8, 1 Rgba16, 2 Gray8, 3 Gray16)
  1  u8   codec (0 raw, 1 zstd, 2 lz4)
  2  u16  reserved
  4  u32  uncompressed length (= format.tile_bytes(), checked)
  8  …    compressed bytes

MANIFEST payload: zstd frame of UTF-8 JSON (M3-T02)

Footer, 64 bytes, always the last 64 bytes written by a save
  0  [u8; 8]  magic "FXDEND01"
  8  u64      offset of the MANIFEST chunk header
 16  u64      MANIFEST chunk total length (header + payload)
 24  u64      end offset of this footer (= its offset + 64)
 32  u64      bytes of live data after this save (header + referenced chunks + footer)
 40  [u8;20]  reserved, zero
 60  u32      checksum of bytes 0..60
```

**API**

```rust
pub struct FxdWriter { … }   // wraps a File opened read+write
impl FxdWriter {
    pub fn create(path: &Path) -> Result<Self, IoError>;          // new file, writes the header
    pub fn append_to(file: FxdFile) -> Result<Self, IoError>;     // after the current footer
    pub fn tile(&mut self, format: PixelFormat, codec: Codec, compressed: &[u8]) -> Result<ChunkRef, IoError>;
    pub fn manifest(&mut self, json_zstd: &[u8]) -> Result<ChunkRef, IoError>;
    /// fsync data, write the footer, fsync again. The previous footer stays
    /// valid until this returns.
    pub fn commit(self, manifest: ChunkRef, live_bytes: u64) -> Result<FxdFile, IoError>;
}
pub struct ChunkRef { pub offset: u64, pub len: u64 }
/// An open .fxd: shared (Arc) by every backed tile of the document.
pub struct FxdFile { … }
impl FxdFile {
    pub fn open(path: &Path) -> Result<(Arc<FxdFile>, Footer), IoError>; // newest valid footer
    pub fn read_chunk(&self, at: ChunkRef) -> Result<(ChunkKind, Vec<u8>), IoError>; // checksum verified
}
```

* Reads use positional reads (`std::os::windows::fs::FileExt::seek_read`,
  `unix::fs::FileExt::read_at` behind `cfg`) so many threads read one handle
  without a lock.
* **Recovery**: if the last 64 bytes are not a valid footer (torn write),
  scan backwards **byte by byte** (footers are not aligned), reading 1 MiB
  blocks, for the magic `FXDEND01`; accept the first footer whose checksum is
  valid and whose "end offset" equals its own position + 64. Log a warning
  with the number of bytes ignored. The next save appends after that footer
  (the torn bytes are overwritten).
* Errors: bad magic → `IoError::UnsupportedFormat`; newer version →
  `Unsupported("fxd version N")`; checksum mismatch → `Decode("corrupt chunk at …")`.

**Tests** round trip of each chunk kind; a flipped byte in a payload → error,
never garbage; the file truncated at **every** byte offset inside the last save
opens the previous version (loop over a small file); header only → "not a
complete .fxd"; two commits → the second manifest is found.

## M3-T02 — Manifest (`Document` ↔ JSON)

**Files** `crates/fx-io/src/fxd/manifest.rs`; `crates/fx-core/src/document.rs`
(accessors only, see below).

* A versioned serde model **in `fx-io`** (`fx-core` stays free of file
  concerns): `Manifest { version: 1, width, height, color, ppi, next_layer_id,
  name_counters, selected, layers: Vec<LayerEntry>, preview: Option<ImageEntry> }`.
  `Document`'s private `next_id` and `name_counters` need
  `pub fn id_state(&self) -> (u64, [u32; N])` and
  `pub fn with_id_state(self, …) -> Self` in `fx-core` (the default names
  "Layer 7" must continue after reopening).
* `LayerEntry` = every `Layer` field (`name, visible, opacity, fill, blend,
  clipped, locked_pixels, locked_position`), `mask: Option<MaskEntry>`
  (`enabled, linked, outside_value, image`), and the kind: `pixel { offset,
  image }`, `group { expanded, children }`, `adjustment { adjustment }`
  (already serde), `solid_fill { rgba }`.
* `ImageEntry { width, height, format, levels: Vec<LevelEntry> }` where
  `LevelEntry { level, derived: bool, slots: Vec<SlotEntry> }` lists **only
  non-empty slots**: `[tx, ty, "s", r, g, b, a]` (solid) or
  `[tx, ty, "t", offset, len]` (tile chunk). Level 0 is authoritative; levels
  ≥ 3 are stored `derived: true` (T00-4); levels 1–2 are not stored (rebuilt
  lazily).
* `to_manifest(doc, tile_ref: impl Fn(&TileHandle) -> ChunkRef) -> Manifest`
  and `from_manifest(m, file: &Arc<FxdFile>, store: &TileStore) -> Result<Document, IoError>`
  (the second builds backed tiles, T03).

**Tests** a document with every layer kind, nested groups, masks (linked and
not), clipping, offsets (negative too), locks and every adjustment kind
round-trips to an equal document; unknown JSON fields are ignored (forward
compatibility); `version: 2` is refused with a clear error.

## M3-T03 — Backed tiles (`fx-tiles`)

**Files** `crates/fx-tiles/src/store.rs` (+ tests). This is Claude's core
code: extend it, do not restructure it (`AGENTS.md` §2).

* A fourth copy in `Copies`: `backed: Option<Backed>` with
  `pub struct Backed { pub source: Arc<dyn TileSource>, pub offset: u64, pub len: u64 }`
  and `pub trait TileSource: Send + Sync { fn read(&self, offset: u64, len: u64, format: PixelFormat) -> Result<TileBuffer, TileError>; fn id(&self) -> u64; }`
  (`fx-io` implements it for `FxdFile`; `fx-tiles` stays free of file formats).
* `TileStore::insert_backed(format, class, Backed) -> TileHandle` — no other
  copy; nothing is read.
* `get()`: hot → warm → cold → **backed** (read + decompress; counts as a cold
  read in `TileStoreStats`, plus a new `backed_reads` counter). The result
  becomes the hot copy as usual.
* Trimming: a tile with a backed copy **drops** its hot/warm copies instead of
  compressing or writing them to scratch (it can always be read again).
* `TileStore::attach_backing(&self, handle: &TileHandle, backed: Backed)` —
  called after a save for every tile written: from then on the tile may
  leave scratch (free its cold extent at the next trim).
* `TileHandle::backing(&self) -> Option<(u64 /*source id*/, u64, u64)>` —
  Save uses it to reuse offsets.

**Tests** get of a backed tile = the right pixels; after `trim` a backed tile
uses no warm/scratch bytes; `attach_backing` then trim frees the scratch
extent; concurrent `get`s of one backed tile return equal buffers and the
source is read at most once per miss (count reads in a test `TileSource`);
dropping the last handle does not read the file.

## M3-T04 — Save, Save As, compaction

**Files** `crates/fx-io/src/fxd/save.rs`, engine wiring in
`crates/fx-engine/src/{engine.rs,documents.rs}` (recipe R2).

`pub fn save(doc: &Document, store: &TileStore, target: SaveTarget, progress: Progress) -> Result<SaveReport, IoError>`
with `SaveTarget::Incremental(Arc<FxdFile>)` or `SaveTarget::Fresh(PathBuf)`.

1. Walk every `TiledImage` of the document (layer pixels, masks, the preview)
   and collect the tiles to store: level 0 of everything, levels ≥ 3 (derived,
   only those present — never compute mips just to save them).
2. Incremental: a tile whose `backing()` source is this file keeps its
   `ChunkRef`. Every other tile: read (`store.get`), compress on rayon
   (T00-2 codec), append **in order** (compression in parallel, writes
   sequential, ≤ 64 tiles in flight — bounded memory).
3. Composite preview: render levels ≥ 3 of the flattened document with the
   CPU reference compositor (as `fx_engine::export` does, at a mip level) —
   only if anything changed since the last save; else reuse.
4. Manifest (T02) → `commit`. Then `attach_backing` for every written tile.
5. Fresh (Save As, compaction): write to `<target>.part` in the same folder,
   `commit`, then `std::fs::rename` over the target (on Windows it replaces an
   existing file). If the target is the document's own open file (compaction),
   close the old `FxdFile` handle first: every tile written is re-pointed to
   the new file with `attach_backing` (it replaces the old backed copy), and
   tiles that only the undo history still references (not written to the new
   file) first get a cold copy in scratch — otherwise undo would lose them.
   Only then drop the old handle and rename (Windows refuses to replace an
   open file).
   Tiles backed by another file are **copied compressed** (read the chunk,
   write it as is — no recompression).
6. Compaction: after an incremental save, if `live_bytes < 50 %` of the file
   length, run a Fresh save to the same path in the background.
7. `SaveReport { tiles_written, bytes_written, tiles_reused, seconds }` → the
   engine logs it and puts it in the toast in debug builds.

Engine: `OpenDoc` gains `file: Option<Arc<FxdFile>>` and `path: Option<PathBuf>`;
Save on a document without a file = Save As. `dirty` is cleared on success
(`DocumentChanged` to the UI). The document stays editable during the save
(the job works on a snapshot); edits made meanwhile keep `dirty = true`.

**Tests** save → change one layer's opacity → save: 0 tiles written, only a
manifest (+ preview) appended; paint one tile → exactly 1 level-0 tile (+ its
mip ancestors ≥ 3 if present) appended; a save interrupted after any chunk
(simulate by truncating the file) → the previous version opens with its
pixels; compaction keeps every pixel and shrinks the file; Save As of a file
opened from another `.fxd` copies without recompressing (count compress calls).

## M3-T05 — Open

**Files** `crates/fx-io/src/{lib.rs,fxd/open.rs}`, `crates/fx-engine/src/engine.rs`.

* `sniff` recognises `FOTOXFXD` → `Sniffed::Fxd`. `import_file` is for flat
  images; `.fxd` gets `fx_io::fxd::open(path, store) -> Result<OpenedFxd, IoError>`
  returning the `Document`, the `Arc<FxdFile>` and the composite preview image.
* Nothing but the footer and the manifest is read. Pixel tiles are backed.
* The engine creates the `OpenDoc` immediately (no progress bar needed below
  ~1 s; show one if the manifest read takes longer), with `file` and `path`
  set and `dirty = false`.
* First frame: the render thread composites from the stored mip ≥ 3 tiles;
  the composite preview is used **as the coverage level** when a tile program
  at the target level cannot be built yet (hook into `plan_frame`'s coverage
  fallback: a preview tile counts as a ready ancestor).

**Tests** opening a synthetic 220-layer file reads < 1 % of its bytes before
the first frame (count bytes in the `TileSource`); open → edit → save → open
equals the edited document; a `.fxd` dropped on the window opens like a TIFF.

## M3-T06 — Engine + UI (save, dirty state, close prompts)

**Files** `crates/fx-app/src/app.rs` (dialogs, like `export_file_dialog`),
`crates/fx-engine/src/engine.rs`, `ui/js/actions.js`, `ui/js/native/documents.js`,
`ui/js/data/dialogs.js`, protocol (recipe R3).

* `doc:save` (Ctrl+S): UI action → engine. With a file, the engine saves
  incrementally (job, recipe R2). Without one (an imported TIFF), the engine
  emits `EngineOutput::NeedSavePath { doc, suggested_name }` — an output for
  the **shell**, not a protocol message, because the shell owns native
  dialogs; the shell shows the save dialog (`.fxd` filter) and sends
  `EngineInput::SaveAs { doc, path }`.
* `doc:save-as` (Shift+Ctrl+S): always the dialog (filter `.fxd`).
* Dirty state: the tab title gets ` *` when `DocumentInfo.dirty`.
* Closing a dirty document (tab ×, Ctrl+W, Close All, quitting the window):
  the UI shows *"Save changes to “name” before closing?"* — **Save / Don't
  Save / Cancel** (a dialog definition `save-changes`). The shell asks the
  engine before closing the window: `EngineInput::CloseRequested` → engine
  answers `EngineOutput::MayClose(bool)` after the prompts.
* Open dialog filters get `.fxd` first ("Fotox document"); drag & drop and the
  command line accept it (`sniff`).
* `doc:revert`: reopen from the file (drop the history), after a confirmation.
* Recent files (`doc:recent*`): out of scope (M8).

**Tests** engine-level: `doc:save` on a document without a file emits
`NeedSavePath`; after `SaveAs` the document is clean; an edit makes it dirty;
closing a dirty document without an answer does not close it.

## M3-T07 — Export, finished

Done (`docs/reports/M3-export.md`): streaming TIFF/PNG writers
(`fx_io::export`, `fx_io::tiff_write`), engine export on the CPU reference
compositor (`fx_engine::export`), *File ▸ Export ▸ PNG / TIFF*, ppi written,
alpha only for non-opaque documents, `fotox-cli export`. Remaining:

1. **Export As dialog** (`export-as` exists as a mock): format (PNG, TIFF,
   JPEG), bit depth (8/16; JPEG 8 only), transparency (default: automatic =
   the current rule), JPEG quality 0–100 (default 90) and chroma (4:4:4 /
   4:2:0). Shown by the UI; OK → the shell's save dialog with the chosen
   extension → `EngineInput::Export { path, options }` (extend the variant).
2. **JPEG** (T00-7): `ExportFormat::Jpeg`; the encoder is not streaming, so
   encode in **strips of 256 rows through its restart-interval / scanline
   API** if it has one; otherwise refuse images above 16 384 px per side with
   a clear message (JPEG's own limit is 65 535) and document it.
3. **TIFF compression** (only if T00-8 says yes): Deflate with horizontal
   predictor as an Export option; `tiff_write` compresses each strip on rayon
   before `write_strip` (Compression tag 8, Predictor tag 317 = 2). Default
   stays uncompressed.
4. **Speed** — GPU readback: render each band's tiles with the GPU compositor
   at level 0 (the same tile programs), copy the composite tiles to a staging
   buffer, map, un-premultiply, hand to `export_image`. The reference
   compositor stays the fallback without an adapter and the test oracle
   (GPU export = CPU export within 1/255 at 8-bit, 1/65535·64 at 16-bit).
   Target: B1 + B3 export ≤ 60 s (CPU today: ~4 min estimated).
5. ICC profile embedding moves to M4 (colour management).

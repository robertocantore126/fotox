## M3-T00 — Decisions (Rob)

1. **Checksum**: `crc32c` (spec) needs a new crate (`crc32c`); `crc32fast`
   (plain CRC-32) is the alternative. Either is fine; pick one.
2. **Tile codec**: zstd level 3 (spec; `zstd` is already a workspace
   dependency, it builds C code) vs `lz4_flex` (already used for warm tiles,
   pure Rust, ~3× faster, files ~20–30 % bigger). S7 favours LZ4 for save
   speed; file size favours zstd.
3. **Manifest**: zstd JSON (spec, easy to debug) — confirm. It grows with
   the tile tables: B1 at 16 bit has 118² ≈ 14 000 slots per image, fine.
4. **Preview chunks**: store the flattened composite at levels ≥ 3 (spec), or
   rely only on per-layer mips ≥ 3. The composite makes S3 trivial and costs
   ~1.5 % of level-0 size per save.
5. **The file stays open (and locked for writing by others) while the document
   is open**, since tiles are read lazily from it. Save As to another file
   copies every tile (no cross-file references). Confirm.
6. **JPEG export encoder**: `jpeg-encoder` (pure Rust) — confirm the crate.

## M3-T01 — `.fxd` container (`fx-io::fxd`)

Header / chunks / footer exactly as `FILE_FORMAT.md`: writer (append chunk,
return its offset; write manifest + footer; `fsync`) and reader (read footer,
validate crc, read a chunk by offset with crc check). **Recovery**: a torn
last footer → scan backwards for the previous valid footer.

Tests: round trip of every chunk kind; crc mismatch → error, not garbage;
file truncated at every byte offset of the last save → the previous version
opens; a file of only a header → "not a complete .fxd".

## M3-T02 — Manifest (`Document` ↔ JSON)

A versioned serde model: size, colour, ppi, layer tree (every `Layer` field,
every `LayerKind`, adjustments — already serde), selection, and per
`TiledImage` its tile table (`Empty` | `Solid(value)` | `Tile(offset, len)`),
mip levels ≥ 3 marked derived. `fx-core` stays free of file concerns: the
model lives in `fx-io`, conversion both ways there.

Tests: a document with every layer kind, group nesting, masks, clipping,
offsets, locks, adjustments round-trips to an equal document (tile tables
compared by content).

## M3-T03 — Backed tiles (`fx-tiles`)

A fourth kind of copy: `backed: Option<Backed { file, offset, len, codec }>`.
`TileStore::insert_backed(...)` creates a tile with only that copy; `get()`
reads + decodes it on demand (like a cold read, counted in stats); trimming
drops the hot/warm copies of a backed tile and never writes it to scratch.
`TileHandle::backing()` lets Save reuse the offset.

Tests: get → the right pixels; trim → no scratch use; the file dropped while
tiles still reference it stays valid (the `Arc` keeps it open); concurrent
gets of one backed tile read it once.

## M3-T04 — Save, Save As, compaction

Incremental Save: for every tile of the document (layers, masks, selection,
derived mips ≥ 3), reuse its offset if backed by *this* file, else compress
(rayon) and append; then previews that changed, the manifest, the footer,
`fsync`. The previous footer stays valid until the new one is complete.
Save As / compaction (dead chunks > 50 %): write a fresh file next to the
target and rename over it. After a save the saved tiles become backed.

Tests: save, change one layer, save → only that layer's tiles appended
(file growth measured); kill mid-save (simulate by truncation) → the
previous version opens; compaction keeps every pixel.

## M3-T05 — Open

`import_file` recognises the `FOTOXFXD` magic: read footer → manifest →
`Document` with backed tiles; nothing else is read. The first frame comes
from the preview / mip ≥ 3 tiles. Per-layer mips below level 3 are rebuilt
lazily (`mips.rs` already builds missing mips on demand).

Tests: open B3-sized synthetic file reads < 1 % of it before the first
frame (count bytes read); a document opened, edited and saved again is equal
to the edited one.

## M3-T06 — Engine + UI

* `doc:save` (Ctrl+S), `doc:save-as` (Shift+Ctrl+S): the shell shows the
  native save dialog (like `export:png`, see `fx-app/src/app.rs`); the engine
  saves as a job with `progress`.
* Dirty state: `*` in the tab title; closing a dirty document or quitting
  asks *Save / Don't Save / Cancel* (a UI dialog; the shell asks the engine
  before closing the window).
* `.fxd` in the Open dialog filters and drag & drop.
* Revert (`doc:revert`): reopen from the file.

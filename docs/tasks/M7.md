# M7 — Everyday basics and tool kinds

> **Draft by Claude (26 Sep 2026), not approved yet.** Refine when M6 is
> accepted. Decisions in M7-T00 first.

Goal: the things a working day needs before any new tool:
- a blank document (File ▸ New), the Move tool, placing a file as a layer;
- Arrange / Align / Distribute and the rest of the Mask menu;
- guides, grid and snapping;
- a menu with no dead ends.

The milestone also builds the **tool kinds**: the extension points that make
each M8 tool a small file plus a test instead of a new pipeline.

Exit criteria (proposed — add to `PERFORMANCE.md` §4 when approved):

| --- | --- | --- |

| S23 | Place Embedded of a 8000² PNG onto B1 | layer on screen ≤ 3 s, UI responsive |

## M7-T00 — Decisions (Rob)

1. **New document defaults.** Photoshop's dialog has presets and remembers
   the last values; **Clipboard** is the default preset when the clipboard
   holds an image. **The same, with Fotox presets: Clipboard, Last Used,
   1920 × 1080 px 72 ppi, A4 300 ppi, 4K UHD, 30 000² (B3 test).**
2. **Move tool's Auto-Select** default. Photoshop ships it **off** (Ctrl+drag
   = auto-select once). **Off.**
3. **Placed files before Smart Objects exist** (M12): Place Embedded makes a
   **pixel layer** (with a Free Transform box to confirm, like Photoshop). When
   M12 lands, placing makes a Smart Object instead. **Yes.**
4. **Menu honesty.** An item the engine does not implement is **greyed out
   with a tooltip "Planned for Mx"**, never clickable with a "not implemented"
   toast. `check-data.mjs` enforces it from a list the engine exports.
   **Yes.**
5. **Preferences file**: `%APPDATA%\Fotox\preferences.json`: units, guide and
   grid colours, grid spacing, memory budget, scratch folder, recent files.
   **Yes** (JSON, versioned, unknown keys kept).

## M7-T01 — File ▸ New

**Files**
- `crates/fx-engine/src/engine.rs` (`doc:new` action with args);
- `crates/fx-engine/src/documents.rs` (`OpenDoc::blank`);
- `ui/js/native/documents.js` and `ui/js/data/dialogs.js` (the `new-doc`
  dialog made live);
- `crates/fx-app/src/window/clipboard.rs` (the clipboard image's size, for
  the preset).

**What to build**
- `doc:new` `{width, height, units, ppi, depth, profile, background:
  "white" | "black" | "background" | "transparent" | [r, g, b]}`. The
  engine builds a document with one `Background` layer, and its tiles are
  `Solid`/`Empty`: **no pixel memory**, whatever the size (One Rule).
- Name "Untitled-1", "Untitled-2"… (Photoshop). Dirty from the start = false
  (Photoshop asks nothing when closing an untouched new document).
- The dialog's Clipboard preset: the shell asks the Windows clipboard for
  `CF_DIBV5`'s header only (width, height), no pixels.
- Ctrl+N, and the doc tabs' "+" button.

**Tests**
- A 30 000² white document has no Data tile.
- "Transparent" gives a normal layer named "Layer 1" (Photoshop), not a
  Background.
- Names increment.
- A `geometry_flow`-style integration test: `doc:new` → `document_opened`
  with the asked size.

## M7-T02 — Move tool (V)

**Files**
- `crates/fx-engine/src/tools/move_tool.rs` (new);
- `crates/fx-core/src/command.rs` (`Command::OffsetLayers`);
- `ui/js/data/options.js` (`move` bar made live).

**What to build**
- Drag moves the selected layers. The drag is shown through the render
  snapshot's offsets (no command per event); the drop is **one** command,
  `Command::OffsetLayers { moves: Vec<(LayerRef, i32, i32)> }` (labelled
  "Move", all or nothing, locked layers refused).
- Offsets only: **no pixel is rewritten** (D-015), whatever the size.
- With a pixel selection, the selected pixels move instead: that is M6-T04's
  `Command::Transform` with a translation (a hole, the moved pixels, the
  selection follows). Whole-pixel translations copy exactly.
- Modifiers:
  - Shift constrains to horizontal / vertical / 45°;
  - Alt+drag duplicates first (Photoshop: the copy moves);
  - Ctrl+drag auto-selects once;
  - the arrows nudge 1 px (Shift: 10 px), and a burst of arrows merges into
    one history step (the `EditKey` merge of opacity drags).
- Auto-Select (option bar: Layer / Group). The layer under the pointer is the
  topmost visible layer whose pixel there has alpha > 0. It is read from the
  layers' own tiles at level 0 for one pixel, never from a composite.
- Show Transform Controls (option bar): the box of the active layer. Dragging
  a handle starts M6-T04's session on that handle.
- Snapping (T06) applies to the moved box's edges and centre.

**Tests**
- A drop is one step and rewrites no tile (handles compared).
- Shift constrains.
- Alt duplicates then moves.
- Arrows merge into one step.
- Auto-select picks the top opaque layer and skips a transparent pixel.
- A selection moves its pixels.
- A locked layer is refused.

## M7-T03 — Place Embedded, and drop onto a document

**Files**
- `crates/fx-engine/src/engine.rs` (`EngineInput::Place { paths }`);
- `crates/fx-app/src/app.rs` (the drop handler, `app.rs:505`: with an open
  document, a drop places; with none, it opens);
- `ui/js/actions.js` (`misc:place-embedded` → the native open dialog).

**What to build**
- The file is imported on a job (the existing import path), becomes a pixel
  layer above the active one, centred. If it is larger than the canvas it is
  scaled to fit, which is Photoshop's "Resize Image During Place" preference,
  on by default.
- Then M6-T04's box is up on it. Enter keeps it; Escape removes the placed
  layer — one step "Place" in both cases (Escape = no step).
- A `.fxd` placed flattens its composite (export path) into the layer.
- Several files dropped: one layer each, in order.

**Tests**
- Place a PNG: the layer, its size and centre.
- An oversize one is fitted.
- Escape leaves the document as it was.
- A drop with a document open places, without one it opens (shell logic unit
  test on the path decision).

## M7-T04 — Arrange, Align, Distribute

**Files**
- `crates/fx-core/src/command.rs` (`Command::ArrangeLayers`, reuse
  `OffsetLayers`);
- `crates/fx-engine/src/engine.rs` (`order:*`, `align:*`, `dist:*`).

**What to build**
- `order:front|forward|backward|back`: within the layer's parent group, as
  Photoshop does (never out of it).
- `align:left|hcenter|right|top|vcenter|bottom`: to the selection's bounds
  when there is a selection, else to the selected layers' common box (or the
  canvas with one layer, Photoshop 2020+).
- `dist:*`: equal spacing of edges or centres; `dist:hspace|vspace`: equal gaps.
- The boxes are the layers' exact content bounds
  (`pixels::content_bounds`, M6-T03), computed on a job when layers are big.
- One command, "Align" / "Distribute" / "Arrange".
- The Move tool's option bar buttons send the same actions.

**Tests**: every action on three offset layers (exact expected offsets);
arrange stays within a group.

## M7-T06 — Guides, grid and snapping

**Files**
- `crates/fx-core/src/document.rs` (`guides: Vec<Guide>`, saved in the
  `.fxd` manifest with `serde(default)`);
- `crates/fx-engine/src/snap.rs` (new);
- `crates/fx-render/src/overlay.rs` (guide and grid lines);
- `ui/js/canvas.js` (drag a guide out of a ruler).

**What to build**
- Guides:
  - `Guide { axis, position: f64 }` in document pixels;
  - drag from a ruler (the UI sends `guide:add {axis, position}` while
    dragging, `guide:move`, `guide:remove` when dropped on the ruler);
  - View ▸ New Guide / New Guide Layout / Lock / Clear, and Show Extras (Ctrl+H).
  - Adding or moving a guide is a history step, as in Photoshop, but does not
    dirty the pixels.
- Grid: from the preferences (every N units, M subdivisions). Only the lines
  in the visible rectangle are generated (bounded by the screen).
- Snapping, one service `Snap::point(p, radius_px, what)`:
  - to guides, grid, canvas edges and centre, layer bounds, and the selection's
    edges;
  - View ▸ Snap / Snap To toggles;
  - used by Move (T02), Marquee, Crop, Free Transform's handles and the Shape
    tools. The tools call `ctx.snap(point)`, so a tool does not know what is
    snapped to.

**Tests**
- Guides round-trip through `.fxd`.
- Snap picks the nearest target inside the radius and nothing outside it, and
  its radius is in screen pixels (zoom-independent).
- The grid lines on screen are bounded at any zoom.

## M7-T07 — Zoom tool and navigation polish

**Files**
- `crates/fx-engine/src/view.rs`.

**What to build**
- Zoom tool: a click zooms in about the point, Alt+click zooms out, a drag is
  Scrubby Zoom (right = in); with Scrubby off, a drag zooms to the rectangle.
- Double-click the Hand = Fit on Screen, double-click the Zoom tool = 100 %.
- Rotate View: Esc resets.

**Tests**: zoom about a point keeps that document point under the pointer;
the rectangle zoom fits the rectangle.

## M7-T08 — Tool kinds (the extension points of M8)

**Files**
- `crates/fx-ops/src/brush/{stroke.rs,op.rs (new)}`;
- `crates/fx-engine/src/tools/{mod.rs,kinds.rs (new)}`;
- `docs/tasks/HOWTO.md` (new recipe R11).

**What to build**
- **`DabOp`**, the per-pixel part of a brush stroke:
  - `fn needs(&self) -> Needs { source_window: Option<radius px>, state: bool }`
    and `fn pixel(&self, before: Px, window: Option<&Window>, k: f64) -> Px`;
  - the engine keeps spacing, pressure, the stroke buffer (opacity ceiling,
    flow build-up), the selection, lock-alpha, undo and the live/replay
    equality of M5;
  - the existing Brush, Pencil, Eraser and Clone become `DabOp`s with **no
    change of output**: M5's stroke tests are the gate;
  - a stateful variant (`StatefulDabOp`) carries a buffer along the path (for
    Smudge and the Mixer Brush in M8).
- **`ClickTool`**: a click (with tolerance options) → a command built from
  the document and the point (Paint Bucket, Magic Eraser, Red Eye).
- **`DragTool`**: a drag with a line overlay → a command at release, with a
  live preview on the visible tiles (Gradient). It reuses M6-T04's preview
  path (visible tiles, view level, latest wins).
- A tool registry: id → kind + option-bar key. HOWTO **R11 "A new tool in six
  steps"**: the op, its params, the registry line, the option bar, the test,
  the report.

**Tests**
- Brush / Pencil / Eraser / Clone outputs bit-identical before and after
  (M5 tests plus a stored-hash test over a fixed stroke).
- A toy `DabOp` (invert) proves the extension end to end.

## M7-T09 — Menu honesty and minimal Preferences

**Files**
- `crates/fx-engine/src/engine.rs` (an `ENGINE_ACTIONS` list, exported by a
  test into `ui/tools/engine-actions.json`);
- `ui/tools/check-data.mjs`;
- `ui/js/data/menus.js`;
- `crates/fx-app/src/prefs.rs` (new).

**What to build**
- Every enabled menu item in `menus.js` is either UI-local or in
  `ENGINE_ACTIONS`; anything else is `dis: true` with `tip: "Planned for Mx"`
  (the milestone from `COVERAGE.md`). `check-data.mjs` fails otherwise.
- The mock-only AI items (Generate, Remove Background…) are greyed with "Planned
  for M13".
- Preferences dialog (Edit ▸ Preferences ▸ General / Units & Rulers / Guides,
  Grid / Performance) reads and writes `preferences.json`. The memory budget
  and scratch folder apply at the next start (the store is sized at start, as
  today).

**Tests**: `check-data` passes; the preference file round-trips and keeps
unknown keys.
